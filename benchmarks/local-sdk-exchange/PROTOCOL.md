# Local SDK exchange benchmark: protocol

Status: fixed on 22 October 2026, before the recorded runs.
Its SHA-256 is in [`PROTOCOL.sha256`](PROTOCOL.sha256). The run records the same digest.
Do not edit this file. Record any deviation in the README.

## Question

How long does one lockstep call take with the local SDKs, and how much of that time is the transport?
How does the current Rust SDK source compare with the released Rust SDK 1.0.0?

A lockstep call is one request, its verified response, one acknowledgement, and its verified response.
In Python this is `LocalClient.call`.
In Rust it is the same sequence of public functions: `LocalRequest::seal`, the frame functions, and `LocalResponse::verify`.

## Exploratory runs before this protocol

Exploratory runs on 22 October 2026 used an earlier version of this harness on the same computer.
They found these medians for one call:

- Rust client and Rust owner, released SDK: 359 µs without spikes and 411 µs with 127 spikes.
- The same with the current source: 43 µs and 91 µs.
- Python client and Python owner: 1487 µs without spikes.
- A framed echo between two processes: 6.4 µs in Rust and 8.1 µs in Python.

These runs set the thresholds of the hypotheses. They are not results.

## Sources

- **Released:** `local/rust` and `local/python` from the tree of the tag `sdk-v1.0.0`.
- **Current:** `local/rust` of this checkout. Its Python package must be byte-identical to the release; `run.py` records the comparison.

## Validity checks

1. Before any timed run, the released and the current Rust owner process a fixed script of requests.
   The script covers valid steps, retries, result lookups, wrong and repeated acknowledgements, a role violation, a foreign run, sequence gaps, and the finish.
   Both must print the same transcript: every output frame and every verification result.
   If the transcripts differ, no timed run starts.
2. Each timed call must return `committed`, its acknowledgement must return `acknowledged`, and each response must pass verification.
   A failed check ends the run with a nonzero status, and the run is invalid.
3. The last step must return 13 as the count, or the requested number of spikes.

## Configurations

| Name | Client | Owner | Spikes per step |
| --- | --- | --- | --- |
| `raw-rust`, `raw-python` | Framed echo of 512 bytes without NCP | Echo process | none |
| `rust-rust-{released,current}-n{0,13,127,500}` | Rust | Rust, same SDK | 0, 13, 127, 500 |
| `python-python-n{0,13,127}` | Python | Python | 0, 13, 127 |
| `python-rust-{released,current}-n{0,127}` | Python | Rust | 0, 127 |
| `rust-{released,current}-python-n{0,127}` | Rust | Python | 0, 127 |
| `phases-{released,current}-n{0,127}` | Rust client and owner in one process | | 0, 127 |

The `phases` configurations time seven parts of one call without a channel.

## Workload

The owner is an echo backend.
Without spikes, each step returns `{"count": 13}`.
With `n` spikes, each step returns `n` sender identifiers from 1 to 1000 and `n` times in tenths of a millisecond.
Each run sends `prepare`, then 500 warm-up calls, then 3000 timed calls, then `finish`.
The client times each call with a monotonic clock.

## Design

Five rounds run back to back.
In each round, every configuration runs once, in an order shuffled with the seed 20261022.
The computer is in normal use. `run.py` records the one-minute load average before each run and the power source.

## Measures

For each run: the median, the 5th, 95th and 99th percentiles, the minimum, and the maximum of the 3000 call times.
For each configuration: the median, minimum, and maximum of its five run medians.
For each pair of released and current Rust configurations: in each round, the released run median divided by the current run median.
The analysis reports the median of the five ratios and their range.

## Hypotheses

These concern the Rust client and the Rust owner.

- **H1.** Without spikes, the median paired ratio is at least 5.
- **H2.** With 127 spikes, the median paired ratio is at least 3.
- **H3.** With 500 spikes, the current run median is lower than the released run median in each of the five rounds.

A hypothesis holds when its criterion holds. Five rounds give no confidence level, so no significance test is used.

All other configurations are descriptive.

## Limits

- One computer, in normal use.
- An echo owner. Real owners add their own work.
- Pipes between two processes on one host.
- One Python interpreter for the Python endpoints.
- The numbers depend on the computer, the operating system, and the toolchains.

## Not claimed

The benchmark gives no real-time bound and no worst-case bound.
It does not rank NCP against another protocol.
It does not measure a change to the Python SDK.
