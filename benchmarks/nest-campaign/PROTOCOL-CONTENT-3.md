# NEST campaign, content part: protocol 3

Status: fixed on 18 November 2026, before the recorded trials.
Its SHA-256 is in [`PROTOCOL-CONTENT-3.sha256`](PROTOCOL-CONTENT-3.sha256). The schedule records the same digest.
Do not edit this file. Record any deviation in the README.

## Question

With revision 7 of the NCP 2 SDKs, does NCP 2 deliver exactly what NEST simulated, with its Python host and with its Rust host: every spike, with its neuron, its step, and, for neurons with precise spike times, the float64 offset of the spike within its step; and every sample of the membrane potential, bit for bit?
Does it do so for neuron models that differ in their numerics, their randomness, and their plasticity?

## Why

[Content protocol 2](PROTOCOL-CONTENT-2.md) showed exact spikes for three networks with the SDKs before revision 3. Revisions 3 to 7 changed the code of the owner and the client.
It compared spike times on the grid only, and no floating-point value: a time rounded to 0.1 µs cannot show a wrong low bit, and a spike count can be right while a value is wrong.

## Method

For each configuration, [`harness/content3.py`](harness/content3.py) runs three processes with the same network and seed:

- **reference:** NEST alone ([`harness/dump_events7.py`](harness/dump_events7.py)) simulates 2 s in one call of `nest.Simulate`, and the complete events of its devices are kept;
- **ncp2-py:** the NCP 2 Python host [`harness/ncp2_host7.py`](harness/ncp2_host7.py) drives the NEST owner [`harness/ncp2_owner7.py`](harness/ncp2_owner7.py) and keeps every received event;
- **ncp2-rs:** the NCP 2 Rust host [`harness/ncp2-rust7`](harness/ncp2-rust7) does the same.

The networks and the devices are those of [`harness/networks7.py`](harness/networks7.py): a spike recorder for every neuron and a multimeter for the membrane potential of the first 20 neurons at every step of the 0.1 ms resolution, both recording to memory with time in steps.
The owner, on revision 7 of the SDKs at the commit that the schedule records, simulates each interval Δ with `nest.Simulate(Δ)`, sends every event of the devices as six typed arrays (spikes: `senders` u32, `steps` i64, `offsets` f64; membrane potential: `vm_senders` u32, `vm_steps` i64, `vm_values` f64), and then clears the devices. A step whose number of spikes differs from the kernel's spike counter fails the trial.
The hosts check the dtype and the rank of each array. The Python host reads the arrays with the SDK's `tolist`, and the Rust host decodes their little-endian bytes; both write the events to JSON, whose float64 numbers read back to the same bits.
The comparison uses exact multisets: a spike is (neuron, step, the eight bytes of its offset), and a sample is (neuron, step, the eight bytes of its value), with neurons numbered from the first neuron of the network. `content3.py --self-test`, which the runner runs before the first trial, shows that each of nine kinds of difference makes the comparison fail: a lost, repeated, or moved spike, an offset or a potential one unit in the last place off, -0.0 for 0.0, a value that is not a number, and a lost sample.

## Configurations

- The networks `alpha`, `brunel`, and `aeif` of the earlier protocols, and five more of `networks7.py`: `hh` (hh_psc_alpha), `izhikevich`, `gif` (gif_psc_exp, with escape noise), `precise` (iaf_psc_exp_ps, with spikes between grid points), and `brunel_stdp` (the Brunel network with stdp_synapse on the excitatory connections). Each has 1000 neurons, 1, 2, 4, or 8 NEST threads, and Δ = 1 or 5 ms: 64 configurations.
- `brunel` with 10,000 neurons, 1, 2, 4, or 8 threads, and Δ = 1 or 5 ms: 8 configurations.

This gives 72 configurations. Three blocks run each configuration once; block b uses the network seed 20261025 + b, as in the earlier content protocols. The order of each block is shuffled with the seed 20261118.
The runner is `content_run.py --protocol 3`, and the analysis is `analyze_content3.py`. The trials time nothing, so they need no controlled conditions.

## Smoke trials that informed this protocol

On 18 November 2026, before this protocol was fixed:

- In NEST 3.10.0, 500 steps of `nest.Simulate(1.0)` with the devices cleared after each step gave the same spikes, offsets included, and the same membrane potentials, bit for bit, as one `nest.Simulate(500.0)`, for iaf_psc_exp_ps, hh_psc_alpha, izhikevich, gif_psc_exp, and iaf_psc_alpha with stdp_synapse, with 1 and with 4 threads. A device cannot be cleared between `nest.Prepare` and `nest.Cleanup`, so the owner uses `nest.Simulate`.
- One trial of `precise`, 2 threads, Δ = 1 ms: both hosts received exactly the 211,487 spikes, all off the grid, and the 399,800 samples of the reference.
- One trial each of `hh`, `izhikevich`, `gif`, and `brunel_stdp`, 4 threads, Δ = 5 ms: both hosts were exact; the networks fired at 4.9, 25.0, 51.2, and 65.0 spikes per second per neuron.
- `brunel`, 2 threads, Δ = 1 ms, seed 20261025: the reference total, 116,876 spikes, equals that of block 0 of the same configuration in content protocol 2.
- The first self-test of the comparison changed a potential to a decimal neighbour that is the same float64; it now changes each value to its adjacent float64.

These trials are not results.

## Hypotheses

- **K1.** In every trial, the NCP 2 Python host receives exactly the reference multiset of spikes, offsets bit for bit.
- **K2.** In every trial, the NCP 2 Rust host receives exactly the reference multiset of spikes, offsets bit for bit.
- **V1.** In every trial, the NCP 2 Python host receives exactly the reference multiset of membrane potential samples, bit for bit.
- **V2.** In every trial, the NCP 2 Rust host receives exactly the reference multiset of membrane potential samples, bit for bit.
- **S1.** In every trial, each owner sent what its host received, and each owner exited with status 0.
- **K3.** For each of the 32 configurations of content protocol 2 and each block, the reference spike total equals that of content protocol 2.

A hypothesis holds when its criterion holds. A trial that fails to run is reported, and then no hypothesis holds.

## Not claimed

The result covers these networks, sizes, thread counts, and intervals, with the payloads of this harness, on one computer with NEST 3.10.0. It covers the byte-stream binding over pipes, not the Zenoh binding. It times nothing.
