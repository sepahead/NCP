## Question

What happens when a local NCP session meets each failure that the profile names, and does any failure make a client accept a wrong result?

## Trials

Every trial uses SDK 1.0.1. A trial is one session of `prepare`, six steps, and `finish`, unless stated otherwise.
The client is `LocalClient` with a 2 s time limit, except in the soak trials.

| Scenario | What happens | Owners |
| --- | --- | --- |
| `flip-c2o`, `flip-o2c` | A relay flips one random bit of one random frame, including its length prefix, from the client or from the owner | Python, Rust |
| `truncate-c2o`, `truncate-o2c` | A relay forwards a random proper prefix of one random frame and closes that direction | Python, Rust |
| `kill-owner` | The client kills the owner with SIGKILL at a random time | Python, Rust |
| `kill-client` | The trial process kills the client with SIGKILL at a random time; the owner must retire and exit | Python |
| `stall` | One step sleeps three times the client's time limit | Python |
| `oversize-response` | One step returns a result larger than the 65,536-byte frame | Python |
| `oversize-request` | The client tries one request larger than the frame | Python, Rust |
| `backend-raise` | One step raises inside the backend | Python |
| `nest-raise` | The NEST owner raises inside a random step of a 2000-neuron Brunel network with 4 threads | NEST |
| `nest-kill` | The host kills the NEST owner during a random step | NEST |
| `soak` | One long session: 300,000 Rust calls or 60,000 Python calls, with memory and descriptor samples every 0.5 s | Rust, Python |

## Design

Three blocks. Each block runs every trial of the plan once, in an order shuffled with the seed 20261026.
Per block, the plan has 200 trials of each `flip` scenario and owner, 60 of each `truncate` scenario and owner, 40 of `kill-owner` per owner and of `kill-client`, 10 of `stall`, 20 of `oversize-response`, `oversize-request` per owner, and `backend-raise`, 10 of each NEST scenario, and one soak per owner.
The runner appends each finished trial to a file and syncs it, and resumes after an interruption.

## Outcome classes

- **completed:** the session finished and every result matched the expected echo.
- **detected:** the client raised a local error (`execution_unknown`, `wire`, `binding`, or a preflight code), received `indeterminate`, or timed out, and then retired.
- **wrong accepted:** the client verified a result that differs from the expected echo. This class must stay empty.

## Hypotheses

- **F1.** No trial accepts a wrong result.
- **F2.** Every frame fault that damaged a frame ends in the detected class.
- **F3.** Every `kill-client` trial ends with the owner retired and exited within 10 s.
- **F4.** Every `stall` trial is detected within the time limit plus 1 s.
- **F5.** Every `oversize-response`, `backend-raise`, and `nest-raise` trial returns `indeterminate` and retires the client.
- **F6.** Every `oversize-request` trial is refused before any write, and the session then completes.
- **F7.** In each soak, the resident memory of client and owner after the first 10 percent of the session grows by less than 10 percent, and the open descriptors do not grow.

A hypothesis holds when its criterion holds.

## Not claimed

The trials cover the local pipe binding on one computer. They give no network, security, or timing guarantee.
