# 1. Executive decision

**Make NCP the exclusive runtime integration boundary between Engram and CREBAIN, Prisoma, Galadriel, and an explicitly selected Haldir deployment. Engram owns NEST construction, neural execution, experiment orchestration, and closed-loop validation. Each other project retains ownership of its own state and decisions.**

This is a design requirement for the implementation agent, not a description of an already delivered integration. NCP should remain a protocol and library boundary, not become a mandatory central broker, a second experiment orchestrator, or a container for arbitrary remote code.

The previous audit's central judgment stands: NCP has useful engineering foundations, but the inspected public surfaces do not establish a qualified, low-overhead native NCP NEST–CREBAIN closed loop. The candidate and consumer documentation explicitly distinguish historical wire-0.8 integrations, a blocked wire-1.0 candidate, and proposed low-overhead work. [S01], [S11], [S13], [S14], [S19]

The highest-value change is **a small execution contract with exact causality and recoverable outcomes**, not simply a faster serializer. An extra logical step of delay can destabilize a controller even when transport time is negligible. An uncertain simulator mutation can invalidate subsequent results even when every subsequent packet is delivered. Both statements are demonstrated under explicit assumptions in Section 9.

## 1.1 Decisions to implement

**A single project-to-project runtime path.** Replace externally exposed Engram Host API integration with actual NCP endpoints. Existing project-local simulation kernels and internal codecs may be reused behind those endpoints. Passing arbitrary legacy Host API objects through an opaque NCP payload does not satisfy this requirement.

**Two execution profiles.** Deterministic lockstep uses exact logical dependencies and permits bounded pausing for required evidence. Real-time sampled control uses explicit source-age, deadline, coalescing, and fallback policies. Do not advertise them as one interchangeable execution mode.

**One owner per mutable backend.** Only Engram's NEST owner advances its neural state. Only CREBAIN's body owner advances its simulated body. One dependent step is outstanding per coupled run unless a separately specified coupling algorithm proves another schedule appropriate.

**Closed-prefix outcomes.** A step is complete only when the required neural and body outcomes are known and joined. An indeterminate mutation retires the affected coupled generation; it does not trigger a blind retry or a pretend rollback.

**Prepared static meaning.** Bind identities, units, component order, missingness, timebase, action phase, authority mode, and resource limits once. Retain dynamic admission and final-effect checks. Do not repeatedly reconstruct the full static contract in every tick.

**Optional Haldir, never ambiguous Haldir.** In direct simulation mode Engram is the sole commander. In gated mode Engram sends typed intent through NCP to Haldir, Haldir is the sole commander, and CREBAIN remains the final executor. Galadriel provides assessments, not permission to actuate. Prisoma records and analyzes; it is not an implicit control-plane authority.

## 1.2 What this report delivers—and does not claim

This document incorporates the previous NCP audit and all 50 proposed acceptance cases, with corrections, additional findings, expanded mathematics, and a cross-repository migration plan. It is self-contained: another agent does not need the conversation to use it.

Three different kinds of checking were performed: source-symbol review, comparison against consumer contracts and NEST documentation, and executable checks of mathematical examples and abstract state models. These are not three independent full implementation audits.

**Actually executed:** the standard-library Python verification program reproduced in Appendix C. Its recorded output is reproduced in Appendix D. These checks establish the stated finite cases and arithmetic, not correctness of the Rust code or the real simulator stack.

**Not executed:** repository builds, Rust or TypeScript tests, NEST runs, cross-process integrations, failure injection into actual services, or performance benchmarks. No repository modifications were made. No measured latency improvement is claimed.

**Source limitation:** public source was inspected through web retrieval on September 5, 2026. An immutable, locally verified multi-repository checkout could not be obtained in this environment. References to `main` are therefore mutable source observations, not pinned audit artifacts. Historical commit IDs appearing in consumer documents are not relabeled as current HEAD. The implementation agent must perform the snapshot gate in Section 12 before relying on exact current-code findings.

The public Engram repository is not a sufficient implementation surface; Prisoma identifies the executable host as `sepahead/Paper2Brain`. This review did not inspect that host implementation. Galadriel's detailed implementation was not fully retrievable during the recheck; its exact current internal schema and detector behavior remain an explicit verification task. Its proposed NCP role can nevertheless be specified without pretending that integration is already qualified. [S14], [S11]

# 2. Corrections and qualifications to the previous audit

The following statements supersede any broader interpretation of the earlier report.

| Verification language | Source inspection, proof under assumptions, abstract-model checks, native integration tests, and performance qualification are different evidence levels. None substitutes for the others. |

# 3. Current consumer fit

## 3.1 CREBAIN

The managed simulator describes one to three declared entities, a 20 ms tick, a six-component position/velocity observation, and a three-component acceleration action. It uses Host API 2.0 with private length-prefixed JSON IPC, not NCP. Its standard profile has exact roster and time checks, explicit availability, and simulator-only authority. The older NCP bridge remains a separate historical integration surface. [S13], [S18]

**What must survive migration:** the interpreted meaning of those vectors, action phase, per-entity availability, failure classifications, exact step plan, and local application receipt. Replacing the transport must not silently change the controller experiment.

**What should not become universal NCP policy:** the fixture's particular roster size, specific injected-fault schedule, initial positions, or controller gains. Those belong in an installed application profile.

A valid migration moves the externally reachable service boundary to NCP. It need not rewrite a correct local body kernel. It must not retain an Engram-to-CREBAIN private Host API channel as an undocumented fallback.

## 3.2 Prisoma

Prisoma's historical NCP observer is passive, wire-0.8-bound, and not qualified against a compatible live producer. Its documentation distinguishes exact source joins, absent language data, fixture evidence, and missing whole-tick detection. Separately, its managed observer contains explicit closed-loop timebase and causal step binding. [S14], [S15]

The target is **general experiment capture first**, conditional scientific analysis second. An experiment with no language variable must remain a valid generic capture; it must not fabricate a language axis merely to satisfy a particular partial-information-decomposition analysis. Analysis eligibility, capture completeness, and transport conformance are distinct outcomes.

Preserve the strong receipt semantics of the managed observer while replacing its cross-project runtime path with NCP. Prisoma should own its evidence store; Engram sends capture data or retrieval requests through NCP rather than writing directly into Prisoma's database or filesystem.

## 3.3 Galadriel

The NCP architecture assigns Galadriel a read-only observation role and an isolated advisory-extension publishing role; it does not make Galadriel core authority or simulation truth. [S11]

The proposed integration must provide sufficient typed evidence for whichever monitor is actually installed. Merely delivering the same six kinematic values used by the controller may be insufficient for a statistical consistency monitor. Covariance, residual definitions, track identity, timestamps, and missingness may be required by the chosen detector profile. These are **proposed preparation requirements**, not an assertion that every current Galadriel entry point already demands exactly that schema.

A monitor must be able to abstain. Missing evidence, stale evidence, uncalibrated statistics, detector alarm, and transport failure must not collapse into a binary "safe/unsafe" result. Detailed Galadriel schema and implementation verification remains mandatory before its adapter is accepted.

## 3.4 Haldir

Haldir is an experimental mission-authorization reference monitor. Its public design admits typed intent against policy and trusted state, then constructs its own NCP command; it is not a transparent command forwarder. Its runtime integration remains historical, and its documentation explicitly withholds production claims pending deployment and bypass-closure evidence. [S19], [S20], [S21]

**Haldir is not needed merely to move NEST outputs into a deterministic simulator.** It becomes useful when the experiment studies policy-constrained action, role separation, authorization failure, or deployment-like command gating.

A gated run must have an explicit Haldir requirement at preparation. Haldir cannot disappear on timeout and cause Engram to start publishing direct commands. An ungated run must declare Haldir absent rather than suggest that an unused gate somehow protects the path.

## 3.5 NCP's role

NCP should own the shared contract, validators, transport bindings, conformance corpus, and narrowly scoped resource and identity rules. Project-specific simulation policy, statistical interpretation, and authorization policy remain with their owners.

The current low-overhead document is proposed architecture, not proof that these paths execute. Its direction is substantially compatible with the requirements here. Prefer implementing and testing that direction over maintaining a rival private dialect. [S01], [S11]

# 4. Source findings and required corrections

**Priority meanings:** P0 affects experiment correctness, state integrity, or an enabled authority boundary. P1 affects required resource behavior, usability, or latency evidence. P2 concerns additional distribution or interoperability scope. A P0 finding is not automatically a security exploit.

## 4.1 P0: loss accounting occurs after intentional coalescing

In the inspected control-loop path, `tick` consumes the latest sensor and then calls `LinkMonitor::on_seq`. The monitor therefore sees consumed positions rather than necessarily every admitted ingress position. Its default reference and threshold are 0.05 and 5. [S02], [S03]

**Counterexample:** all sensor positions 1 through 9 arrive, but a slower controller consumes 1, 5, and 9. Treating each three-position skip as loss produces successive accumulator values 2.8 and 5.6, crossing threshold 5. This is a consumption schedule, not evidence that three packets were lost on each interval. Section 9 derives the arithmetic; Appendix C checks it.

**Correction:** perform authenticated/session-bound stream accounting at ingress, before a latest-value replacement. Maintain separate counters for ingress gaps, rejected frames, duplicates, late reconciliation within its declared window, local coalescing, and consumed age. An ingress gap still does not prove where loss happened, much less malicious interference.

**Acceptance:** test 06 must deliver every frame and show zero ingress loss despite decimation. Do not disable real gap detection merely to make this case pass.

## 4.2 P0: consumption time is not original receipt time

The inspected path updates `last_sensor_t` with the tick's `now` when a sensor position advances. The latest-slot interface does not preserve an ingress timestamp in that returned sensor envelope. [S02]

An otherwise valid frame can wait during a controller stall and appear newly received when finally consumed. Carry immutable receiver-clock receipt metadata across the local boundary. Replays and unchanged positions must never refresh it.

That correction bounds only post-ingress age. For source-to-effect freshness, use the source-bound grant in Section 7. Never subtract unrelated monotonic clocks or renew a source budget at every relay.

## 4.3 P0: codec output can hide absence or ambiguous layout

The inspected codec validates finite ranges and rejects certain duplicate mappings, but missing inputs/readouts use midpoints, sparse components are zero-filled, and a channel's unit follows the last processed mapping. Its checked paths do not make an arithmetic midpoint universally neutral. [S04]

For a hypothetical command range `[0,10]`, absent readout becoming `5` is a counterexample to universal neutrality. A fallback may be legitimate, but must have a declared disposition and must not masquerade as observed neural output.

Prepare an exact layout with availability semantics, consistent per-component units, and a declared missing-input policy. Reject unintentional holes and contradictions. Keep available zero, unavailable value, available empty spike window, and missing recording evidence distinct. A fixed-width absent slice can contain bounded inert bytes, but consumers must not interpret those bytes as measurements.

## 4.4 P0 for admitted scales: small ranges collapse in interpolation

`validate_range` allows strictly positive finite spans, while `lerp` treats spans smaller than machine epsilon as zero. The range `[0,2^-60]` is therefore admissible yet maps its upper endpoint to the output minimum in that helper. [S04]

This is a numerical consistency error, not a claim about current default UAV ranges. Machine epsilon near 1 is not a universal physical-unit tolerance. For finite validated nonzero spans, compute the normalized fraction under an explicit overflow/underflow policy; alternatively reject unsupported scales during preparation. Add endpoint and unit-rescaling tests. The executable example returns 0 for the source pattern versus the mathematically required 200 for an output range `[0,200]`.

## 4.5 P0/P1: idempotency protects mutation better than outcome recovery

The inspected store retains pending records during expiry cleanup; capacity reclamation can evict non-pending records before their nominal expiry. `begin` checks request timing and live authority before finding a prior record. Its terminal state stores a responder receipt, not an arbitrary full result payload. It also has explicit retry/state protections and an `outcome_unknown` outcome. [S05]

**Do not infer demonstrated duplicate execution from eviction alone.** The important design questions are whether the exact result remains retrievable, whether a permanently pending operation has a containment path, and what retention was actually promised.

For the lockstep profile, reserve one pending operation and one exact result until acknowledged. Preserve a high-water mark after payload release. A duplicate cannot become a fresh mutation merely because its payload was evicted. Authorize result lookup independently of new execution, with no unauthorized disclosure.

If execution may have occurred and its outcome cannot be reconstructed, retire the coupled generation. If serialization or result-budget enforcement fails after mutation, do not label the operation "rejected before execution."

## 4.6 P1: bounded CUSUM work changes permitted detector behavior

The loss monitor caps per-gap observation work at 256 misses, while its configuration accepts larger positive thresholds. Its retained missing-position set is also finite. [S03]

For 1,000 misses followed by one delivery with reference 0.05, the uncapped final accumulator is 949.95; the 256-miss calculation is 243.15. A threshold of 300 separates those decisions. The default threshold would still be crossed, so this is not a claim that every large gap is missed.

Use the exact constant-work recurrence in Section 9, reject unsupported numeric regimes, and decide whether the detector reports the final state or any crossing during the batch. These semantics differ. State the bounded late-reconciliation policy rather than implying exact lifetime loss reconstruction.

## 4.7 P1: thread-local origins are not a movable object's clock

The default clock helper uses a thread-local `Instant` origin. A loop that is moved and subsequently invoked on another thread can therefore encounter a different elapsed-time origin. The tick path has a non-regression check, so the issue can manifest as spurious failure/hold rather than a silent acceptance bypass. [S02]

Use a stable per-owner origin or a properly defined process-wide origin. Store elapsed integer durations where practical. A two-origin counterexample is checked in Appendix C; an actual cross-thread Rust regression is still required. This finding is conditional on migration and is not evidence that the current deployment actually migrates the loop.

## 4.8 P1: strict horizon behavior needs one executable definition

NCP's own limitation ledger records a normative/executable horizon discrepancy and a generic TypeScript validation mismatch. [S10]

For future setpoint positions strictly before expiry, use the formula in Section 9, including the maximum TTL clamp and the count cap. Test exact expiry, fractional cadence, extreme finite inputs, and unsupported ratios through every public validator. A helper passing in one language is not generic-path conformance.

## 4.9 P1: exact contract verification accepts missing identity

`ContractStatus::is_match` accepts `NotAdvertised`; `verify_contract(None)` succeeds. That is documented behavior, but a name implying exact agreement is misleading. The generic decoder also materializes a JSON value before typed conversion. [S06]

Separate compatible-version status from proven prepared-contract identity. A strict prepared session requires the exact selected descriptor or explicitly negotiated compatible descriptor; absence is not proof of identity. Do not use a short advisory hash as authentication or as a collision-resistant evidence commitment.

## 4.10 P0 for secure profiles: transport identity is not established by a payload claim

The reviewed ingress feasibility study says the evaluated direct Zenoh interface does not provide the verified remote principal needed by the proposed secure admission path; that path remains unavailable rather than silently succeeding. The current grant structure principally expresses plane-level permissions rather than all proposed per-operation restrictions. [S09], [S12]

This is a claim about the reviewed integration, not a claim that no future Zenoh version or deployment can supply suitable authentication. The implementation agent must verify the exact selected upstream version.

Keep unavailable security profiles fail-closed. Local private NCP transport must be selected and scoped explicitly; it must not be a silent downgrade. Bind authenticated or locally established origin to role, session generation, route, operation, audience, and resource scope at preparation and admission.

## 4.11 What is worth retaining

Retain bounded parsing, duplicate-key rejection, exact numeric identity rules, explicit generations, restrictive malformed-command handling, and the distinction between local admission and downstream execution. These are useful foundations, not expendable bureaucracy. [S02], [S06], [S07]

The optimization target is repeated work and unclear meaning. It is not removal of the checks that make untrusted messages safe to interpret.

# 5. Low-overhead implementation: remove repetition, not guarantees

The inspected transport validates sensor bytes and later decodes them again in the control adapter. Command handling performs bounded serialization before subsequent publication serialization; publication can copy byte slices. Its observation worker calls synchronous user code while draining a bounded queue. These are source patterns, not measured performance costs. [S08]

The bounded writer reserves up to 64 KiB initially. Active plant-command validation calls profile validation again. Neither observation establishes the time saved by changing it. [S07], [S17]

## 5.1 Prepared objects and typed ownership

Introduce a small validated object graph:

```
PreparedRun
  identity and installed semantic descriptor
  exact time plan and participant bindings
  immutable layouts and explicit availability rules
  resource reservations and selected authority mode

Received<T>
  validated typed value or immutable validated bytes
  exact ingress identity and receiver-local receipt time
  ownership of its resource reservation
```

These names are proposed design labels, not existing API declarations.

Decode once per trust boundary and keep the result. Pass immutable ownership rather than raw bytes that force the next layer to rediscover meaning. Serialize the final committed publication once after its final stream identity is assigned. A pre-execution size check must still guarantee that the eventual output is representable within its reservation.

Static checks include unit compatibility, bounds, layout shape, canonical descriptor identity, and installed policy structure. Dynamic checks include current generation, next expected step, actor scope, lease/currentness where applicable, original source grant, numeric payload validity, and result capacity.

Removing repeated profile hashing is safe only if the object is immutable or replaced atomically by a new generation. A shared mutable object with a stale "validated" flag is not a prepared contract.

## 5.2 Queue and memory policy

Bound aggregate retained bytes, not just item count. The illustrative capacity of 64 one-MiB payloads is 64 MiB before queue objects or transport storage. This calculation does not assert that normal small-frame operation consumes that amount.

For every queue, specify owner, item ceiling, byte ceiling, maximum age, overflow decision, release condition, and teardown behavior. Include transport buffers, result retention, extension attachment reservations, and fan-out. Sharing one immutable payload can reduce copies, but each additional retention reference still delays reclamation and must be accounted for.

A useful conservative reservation equation is

$$
M_{reserved}=M_{fixed}+\sum_j B_j+\sum_s R_s+M_{scratch},
$$

where $B_j$ bounds each owned queue and $R_s$ each retained result. Count shared allocations once in actual memory telemetry, but do not overcommit reservations on the assumption that sharing will always occur.

A full queue rejects work before state mutation or applies the selected coalescing/drop policy. It must not accept a step, mutate NEST, and only then discover that the required result cannot be retained.

## 5.3 Observer isolation

An asynchronous function name does not isolate synchronous user work. Use a bounded dedicated worker or a separate process when callbacks can block indefinitely. Do not spawn unlimited replacement tasks for stalled consumers.

Recording, statistical analysis, visualization, compression, and remote upload stay outside the fast path unless the profile explicitly makes their result a causal dependency. For lossless lockstep capture, reserve space before advancing; pausing can occur at a defined boundary. For real-time best effort, record loss and do not claim complete evidence.

Use immutable observation projections with no commander credentials. A GUI, logger, or embedded presentation panel cannot become a hidden source of controller input or authority.

## 5.4 Transport selection

Start with a small strict NCP local binding over a private process channel or properly permissioned local socket. Its framing, operations, errors, resource admission, and conformance corpus belong to NCP. The fact that the underlying channel is a pipe does not make it non-NCP; the fact that a payload is labeled NCP does not make an arbitrary legacy API conforming.

Preserve a network binding where it is useful. Add compact fixed-layout frames only after profiling shows that small-message encoding/copying is material. A binary encoding must retain version identity, bounded lengths, byte order, finite-number policy, exact integers, and availability padding rules.

Do not mandate shared memory, zero-copy, lock-free queues, busy polling, real-time scheduling, or per-frame signatures by default. Each has assumptions and operational costs. Optimize the measured bottleneck for the selected profile.

# 6. The NCP-only ecosystem boundary

## 6.1 Allowed topology

Every arrow below is an NCP project-to-project interaction. Private execution inside one owning service is not an extra ecosystem API.

```
DIRECT SIMULATION MODE

Engram [orchestrator, NEST owner, sole commander]
    <---- NCP ----> CREBAIN [body state, final application]
    <---- NCP ----> Prisoma [capture, analysis, retrieval]
    <---- NCP ----> Galadriel [observation, advisory output]

GATED MODE

Engram -- NCP typed intent --> Haldir -- NCP command --> CREBAIN
CREBAIN -- NCP observation/disposition --> authorized consumers
Engram -- NCP neural evidence --> Prisoma and Galadriel
Galadriel -- NCP advisory --> Haldir and authorized Engram roles
Haldir -- NCP decision evidence --> Engram and Prisoma

All required evidence reaches Prisoma through NCP.
Engram has no direct plant-command capability in gated mode.
```

The drawings express role relationships, not a required centralized routing service. Observation fan-out can be direct to subscribed NCP peers. Haldir does not need to forward all telemetry. Credentials and routes should be granted to roles, not indiscriminately to an entire repository or desktop process.

The direct/gated separation agrees with NCP's proposed ecosystem direction. Its integrated Haldir proposal also separates extension ingress, policy state, and commander responsibilities. This report preserves the separation but requires measured, threat-model-driven process placement rather than assuming that more processes are automatically safer or faster. [S11]

## 6.2 Explicit prohibitions

The delivered Engram runtime must not integrate with these projects through direct engine imports, a parallel Host API, custom HTTP/WebSocket endpoints, ad hoc pipes, shared mutable storage, file polling, or manually interpreted raw transport taps. It must not smuggle the old interface through a generic "execute" extension.

A project-local worker is allowed only within the owner's declared trust boundary. For example, Engram may privately supervise a NEST worker that has no CREBAIN, Haldir, Galadriel, or Prisoma credentials. CREBAIN may keep its simulation kernel as an internal library. These are not permission to host another project's externally controlled runtime under an Engram-shaped name.

Cross-repository editing, compilation, downloaded build dependencies, and isolated unit-test baselines are development activities, not production integration paths. Their presence must not leave a runtime bypass enabled in a qualified package.

## 6.3 Enforceable connection policy

At preparation, install a role allowlist binding peer identity, allowed operations, exact session kind, route or endpoint, and direction of data flow. Refuse unknown peers and implicit fallback. Give observer roles no mutation capability. Give the gate-intent publisher no final-command capability.

Enforce this in layers: package/dependency checks for forbidden adapters, endpoint configuration, narrowly issued credentials, sandbox egress and inherited-handle policy, and runtime connection tracing. Static searches alone miss dynamic imports and runtime routing; packet capture alone misses local shared-state bypasses. Test both the intended route and deliberate bypass attempts.

The agent should be unable to acquire command authority by reading a GUI projection, calling a helper process with broad inherited credentials, or writing a sidecar file. An evidence dashboard is not a privileged integration surface.

## 6.4 Resource and code authority during simulation creation

Engram may generate and validate a simulation specification and create its local NEST network. Externally supplied model configuration is data under a bounded schema, not unrestricted Python execution requested by a peer.

Prepare separately budgets model size, connection count, initialization memory, execution duration, and recording volume. A cheap per-step frame limit does not prevent a configuration from requesting an enormous simulation. Cancellation during construction must have an explicit cleanup and worker-retirement path.

# 7. Execution contract: exact steps, original freshness, known outcomes

All operation names and data structures in this section are proposed semantic requirements. Reuse compatible existing NCP operations where possible; introduce explicit versioned extensions where necessary. Do not create a second private contract.

## 7.1 Prepare

A prepared descriptor binds the run identity and generation, each participant's role, exact semantic contract identity, participant generations, roster and layout, neural model/build identity, seeds and reproducibility policy, timebase, number of steps, sampling/application phase, permitted intervention points, authority mode, observer mode, and resource reservations.

It also declares which values are *data*, which are *availability*, which are *proposals*, and which are *evidence of application*. A descriptor hash records identity; its presence does not establish that the producer implemented the descriptor honestly.

`prepare` must not itself create final command authority from a caller's self-asserted role. The receiver binds authority to the established principal and selected session. A compact local capability can be opaque and receiver-owned; it need not be an elaborate transferable token.

## 7.2 Step

For a simple sample–neural-run–apply schedule:

$$
y_k=H(x_k),\qquad
(z_{k+1},u_k)=N(z_k,y_k),\qquad
x_{k+1}=P(x_k,u_k).
$$

The state includes all relevant neural, plant, controller, random-generator, and online-monitor state. The input $y_k$ includes declared availability, not just numeric values. $P$ includes application-time constraints and may produce a bounded or fallback action distinct from $u_k$.

A step request identifies the prepared generation, exact step, exact input predecessor, operation identity, and bounded payload. The result identifies the exact request, resulting state position, applied or proposed action as appropriate, and terminal outcome.

One dependent step is outstanding. Do not batch future steps that depend on as-yet unknown plant observations. Batching independent sessions, transport writes, or evidence records is different and may be useful.

Do not require full-state hashing on the hot path solely for appearances. Bind the needed identities and exact result; compute larger evidence commitments on a reserved, ordered capture path when that satisfies the selected completeness policy. A hash chain cannot substitute for missing causal fields.

## 7.3 Local outcome state machine

```
Ready
  -> RejectedBeforeExecution -> Ready
  -> Executing
       -> CommittedWithRetainedResult
            -> ResultAcknowledged -> Ready
       -> Indeterminate -> Retired
Ready -> Finished
```

A known failure before mutation is not indeterminate. A failure after mutation is not necessarily committed unless the backend's commit boundary and outcome are actually known. The API must expose these distinctions instead of using one generic timeout exception.

A matching retry retrieves the same retained result. Same operation identity with different semantic input is a conflict. Result lookup does not rerun the model. Payload acknowledgement releases retained bytes but not the high-water mark that prevents stale execution.

Use an explicit acknowledgement or a precisely defined next-step acknowledgement. The next request can acknowledge the prior result only when the requester possesses that exact result identity; merely requesting a higher index is insufficient.

No unbounded pending cache is necessary for one-in-flight lockstep. General concurrent lifecycle operations can use a different bounded store, with their own contracts.

## 7.4 Coupled commit is not an atomic transaction

NEST and CREBAIN are separate state owners. Without a qualified rollback/checkpoint mechanism, the orchestrator cannot make their advances atomic merely by wrapping them in a method called `step`.

Distinguish `NeuralCommitted(k)`, `BodyCommitted(k)`, and `PairClosed(k)`. The last means the required exact outcomes are known and joined—not that a distributed database transaction occurred.

If the neural advance completes but body application is uncertain, stop advancing the coupled run. Retire the run generation and participating mutable state that would otherwise be reused inconsistently. Preserve the maximal closed prefix and the incomplete suffix as different evidence classes.

A recovered result can resolve a temporary uncertainty only under a specified recovery protocol while no dependent mutation has proceeded. In the initial lean profile, prefer bounded result recovery followed by retirement on unresolved uncertainty. Do not implement opaque speculative recovery.

Independent sessions can continue. A failure in one run does not justify a global process lock or the destruction of unrelated experiments.

## 7.5 Source-bound freshness without synchronized clocks

For a real-time sampled profile, CREBAIN can issue an opaque source grant with each observation. Before publishing, the body owner records the source identity and a deadline on its own monotonic clock. The returning command carries that exact reference; relays do not restart its lifetime.

At final application the body checks the reference against its retained record and compares current body time with the original body deadline. Both times belong to one clock. This includes outbound transport, computation, gate traversal, queuing, and return transport without an extra freshness round trip.

Use a bounded retained-grant window. If the source record has been evicted, reject or use the declared fallback; never substitute "latest." Authentication and exact generation binding are still required. A guessed source identifier is not authority.

This bounds age from the body's recorded event. If a camera captured the observation earlier, its acquisition age needs a trusted mapping or conservative bound as well. The mechanism does not magically prove external sensor time.

For deterministic lockstep, exact predecessor and step checks govern scientific validity. A wall-clock timeout remains a liveness/containment policy, not permission to relabel an old logical input as current.

## 7.6 Cancellation, restart, and finish

Cancellation is a request to stop further work, not evidence that a synchronous backend rolled back. A non-returning NEST worker may require process termination. An uncertain old generation remains retired after restart.

A new run gets new generation identities, fresh neural and body state or an explicitly qualified checkpoint, and a fresh authority context. Do not reuse an old latest-value slot or observer join state.

Finish states planned and completed step counts, the last closed pair, any incomplete suffix, capture completeness, outstanding dispositions, and the reason for termination. A partial run can be useful evidence, but must not be represented as successful completion of the exact full plan.

## 7.7 Final-effect currentness and revocation ordering

Application-time checking needs a precise event order. The body owner should serialize receipt admission, source-grant validation, authority changes, and effect invocation under one bounded ownership model. No user callback, network call, or long simulator operation may run under a realm-wide authorization lock.

Define revocation effectiveness as an event accepted by the designated authority/body owner, with an explicit ordering relative to applications. A command ordered after effective revocation cannot use the old term. A command already irreversibly applied before that event cannot be retroactively undone by a later message. Network delivery of a revocation request is not the same as its acceptance at the final executor.

If authority can change concurrently outside that owner, use a versioned currentness mechanism with a final recheck that actually closes the check/effect race under the implementation's concurrency model. A stale pointer to a "verified" policy snapshot is not sufficient. The initial local simulation profile can avoid unnecessary concurrency by keeping all mutation in its single owner.

Prepared extension receivers must not increase a capability's scope. An advisory or intent admission receipt can bind evidence and narrow a decision; it cannot be exchanged for a broader role token. Emergency messages still require the correct authenticated/local origin and exact live generation, even when they do not require an ordinary active-command lease.

# 8. Consumer-specific implementation requirements

## 8.1 Engram and NEST

NEST documents persistent run control through `Prepare`, `Run`, and `Cleanup`, and a `RunManager`; `Simulate` performs preparation/cleanup and is not equivalent to `ResetKernel`. `ResetKernel` destroys network state. The documentation restricts which changes are meaningful during prepared execution. `local_spike_counter` is reset per `Run`. [S22]

**Implementation:** build the network once per run generation, preserve state across steps, and qualify the exact update path. Create a support matrix naming NEST version/build, model/device, allowed parameter mutation, calibration boundary, effective interval, and observed response. Unsupported live changes fail during preparation, not after silently doing nothing.

Record the neural resolution, stimulation schedule, event-readout convention, and simulation-advance duration. Every requested advance must be representable by the selected backend. A rational common timebase does not make an arbitrary real-valued duration executable by NEST.

Separate reset-per-run counters from cumulative counters. For event records, determine the exact inclusion convention and precise-time representation with boundary tests. NEST's spike recorder reports spike creation times and documents its recording interval behavior; do not infer full window semantics from a generic timestamp name. [S23]

Avoid repeatedly copying an ever-growing historical event array to obtain the latest window. If work at step $k$ is proportional to $k$, cumulative extraction work over $n$ steps grows as $n(n+1)/2$. Use a bounded current-window path or a suitable declared counter; reserve full event capture separately.

Population-rate readout must bind population membership, available event count, window duration, and effective population size. An empty observed window is zero events; a failed readout is unavailable. Rate-estimation noise belongs in the controller design, not in a misleading protocol latency claim.

Record thread/MPI placement and runtime contention. Reproducibility must be declared as bitwise, tolerance-based, or statistical for the selected build and execution configuration. Protocol identities do not make arbitrary parallel simulations bitwise reproducible.

## 8.2 CREBAIN

The target adapter must preserve position, velocity, and acceleration as different quantities with explicit coordinate frames. Reuse the current deterministic body update semantics as a baseline, including availability and local commit behavior, without making its fixture-specific choices universal. [S13]

The receiver must distinguish a controller proposal, a bounded proposal, a fallback disposition, and the action actually applied. Return the exact source reference and resulting state position. Current authority and source validity are checked immediately before effect, not only when a message is placed in a queue.

Zero acceleration is not a universal physical stop. In this simulator it may be a declared hold action; velocity can remain nonzero. The physical-plant profile needs its own actuator semantics, watchdog, and independent deployment evidence.

Use a test-only direct oracle to compare numerical trajectories with the NCP adapter. The distributed runtime must not be able to switch to that oracle when the NCP connection fails.

## 8.3 Prisoma

Define a project-neutral causal capture record that can bind preparation, source observation, neural request/result, controller proposal, gate decision when selected, body disposition, resulting observation, and terminal run status. Preserve each event's actual producer role.

Completeness cannot be inferred only by joining the records that happened to arrive. Retain a run plan and terminal/high-water evidence so omission of an entire step is detectable. If the terminal record is missing, mark completeness unresolved, not successful.

Out-of-order delivery requires bounded joins by exact identity, not nearest timestamp. Exact duplicates can be idempotent; changed payload under the same committed identity is a conflict. Large attachments require separately budgeted ownership and immutable identities. They must be transferred through a declared NCP mechanism, not via arbitrary remote URLs or a shared directory that bypasses the boundary.

An evidence hash attests to byte identity under its construction. It does not prove that NEST really ran, that a remote sensor was truthful, or that a compromised producer did not fabricate a result. Scientific claims require the relevant independent evidence.

Generic capture must be useful even when a specific PID analysis is ineligible. Missing variables remain absent. Do not require a per-tick PID calculation, synthesize a language embedding from a hash, or put an offline estimator on the control path to make a dashboard look complete.

## 8.4 Galadriel

Prepare a named monitor profile that specifies accepted evidence, component/unit conventions, required covariance or uncertainty metadata, track/run identity, missing-data behavior, calibration identity, output vocabulary, and validity interval. The actual Galadriel implementation must be checked against this profile before claiming compatibility.

For an innovation-based example, a residual is $r=y-\hat y$ and a positive-definite innovation covariance is $S$. The normalized statistic is

$$
q=r^\mathsf{T}S^{-1}r.
$$

An implementation should solve using a suitable factorization rather than explicitly computing an inverse. If $r$ is zero-mean Gaussian with covariance $S=LL^\mathsf{T}$, then $v=L^{-1}r$ has identity covariance and $q=v^\mathsf{T}v$ is a sum of squared independent standard-normal components. This derives the chi-square reference law under those assumptions; calling a matrix "covariance" does not establish them. A singular or invalid covariance requires an explicit unsupported/abstention path, not undisclosed numerical repair. Temporal correlation, parameter fitting, multiple testing, and missing observations affect calibration. A large statistic establishes inconsistency relative to a model, not malicious intent.

These are mathematical design requirements, not claims that the current detector implements every listed condition. The first cross-repo Galadriel task is to inventory its real evidence schema, accepted models, and documented limits.

Separate two modes. In **monitoring mode**, assessments are asynchronous and cannot affect the experiment's state transition. In **online-guard mode**, the required assessment for step $k$ is a declared dependency with a deadline and explicit stale/abstention handling. A nondeterministically selected "latest assessment" is not acceptable in a deterministic run.

An advisory may preserve or remove existing permission according to policy. It cannot create command authority. A transport failure is not automatically a detector alarm, and a detector's abstention is not automatically a nominal result.

## 8.5 Haldir

The role is policy-constrained admission of intent, not neural computation, sensor truth, or evidence storage. Existing public Haldir material separates publication from downstream application and does not establish a production deployment. Its declared-live limitations include the lack of adequate application/freshness evidence for continued live operation after publication. [S19], [S21]

In gated simulation mode, Engram publishes semantic intent through a registered NCP extension. Haldir independently checks actor, exact run context, policy, input currentness, and relevant advisory conditions. It then constructs a new command under its own sole body-issued authority. It does not re-sign or forward Engram's command bytes as though authority had transferred with them.

CREBAIN still makes the final admission and effect decision. Haldir must reconcile the body disposition rather than infer success from a successful publish call. Source grants and application receipts address necessary protocol gaps, but do not by themselves solve credential custody, bypass closure, or physical deployment safety.

Keep the intent receiver, advisory receiver, policy owner, and commander capabilities distinct. Process isolation can enforce meaningful trust separation, particularly around untrusted extension parsing. The simulation preview can choose a smaller explicitly weaker local profile, but must not represent it as the fully isolated deployment profile.

On missing or indeterminate Haldir output, use the declared stop/hold/termination policy. Do not fail open to direct Engram command. Changing authority mode requires a new prepared authority term or run generation with independently admitted scope.

# 9. Mathematical contracts and executable checks

The proofs below are under stated mathematical assumptions. Appendix C checks finite instances and counterexamples. It does not constitute formal verification of the repositories, machine arithmetic in every regime, or a physical controller.

## 9.1 Strict horizon count

Let $L=\min(TTL,TTL_{max})>0$, cadence $d>0$, and integer count cap $C\ge0$. Future setpoint $j$ executes at offset $jd$ for integer $j\ge1$. Expiry is strict: $jd<L$.

The largest allowed integer is therefore

$$
N=\min\left(C,\max\left(0,\left\lceil\frac{L}{d}\right\rceil-1\right)\right).
$$

**Proof.** For positive $x=L/d$, integers satisfying $j<x$ are exactly $1,\ldots,\lceil x\rceil-1$. Apply the nonnegative and count caps. For integer time ticks, use the overflow-aware equivalent $\lfloor(L-1)/d\rfloor$ before the count cap. Zero/invalid lifetimes are rejected or handled explicitly before this positive-input formula.

At $L=40$ ms and $d=20$ ms, only the future position at 20 ms is valid; the position at 40 ms is expired. A `floor(L/d)` rule would include one too many at exact division. Exact integer/rational arithmetic also avoids overflow in a floating-point `TTL/d` ratio.

**Check:** enumeration of executable positions over a finite rational grid, plus integer-boundary cases. This validates the formula, not current TypeScript or Rust parity.

## 9.2 Constant-work CUSUM batching

For nonnegative accumulator $s$, reference $0\le r<1$, and $m\ge0$ missing events followed by one delivered event, define a loss update as $s\leftarrow\max(0,s+1-r)$ and a delivery update as $s\leftarrow\max(0,s-r)$.

Because every loss increment is nonnegative, the exact final state is

$$
s'=\max\left(0,s+m(1-r)-r\right).
$$

This replaces $m$ updates with constant arithmetic work. It does not make finite machine arithmetic exact; choose checked fixed-point/rational behavior or a justified floating-point error policy and handle huge sequence gaps explicitly.

For consumed positions 1, 5, 9, each observed gap has $m=3$. With $r=0.05$ and initial $s=0$, the states are 2.8 then 5.6. With $m=1000$, the state is 949.95; truncating to $m=256$ gives 243.15.

**Important distinction:** whether any intermediate event crossed a threshold is not identical to whether the final state exceeds it. A delivery can reduce an accumulator below threshold. If transient crossing latches a condition, compute the peak as well and define exactly which histories matter. Do not change detector semantics accidentally during optimization.

## 9.3 Exact common timebase

For positive rational durations $d_i=p_i/q_i$, let $Q$ be the least common multiple of denominators and $a_i=p_i(Q/q_i)$. A common quantum is

$$
\delta=\frac{\gcd(a_1,\ldots,a_n)}{Q}.
$$

Then every $d_i/\delta$ is an integer. Store logical time as integer tick position and compute $t_k=k\Delta$ without repeated floating-point accumulation. Check representability and overflow before preparation; denominator growth must be bounded.

For a 0.1 ms neural resolution and 20 ms control interval, 200 neural ticks make one control interval. One million intervals correspond exactly to 20,000 seconds under that declared rational model.

This construction does not prove that a backend accepts the chosen quantum or that a particular live-update mechanism acts at its boundary. Those are integration tests.

## 9.4 One hidden step of delay changes stability

Consider the scalar integrator with feedback

$$
x_{k+1}=x_k+\Delta u_k,\qquad u_k=-Kx_k,
$$

and define $a=K\Delta$. Without added delay, $x_{k+1}=(1-a)x_k$, which is asymptotically stable exactly when $0<a<2$.

If an integration error applies the previous observation instead,

$$
x_{k+1}=x_k-a x_{k-1}.
$$

Its characteristic polynomial is $z^2-z+a$. For $0<a\le1/4$, the real roots lie inside the unit circle. For $1/4<a<1$, they are complex conjugates with product $a$ and modulus $\sqrt a<1$. At $a=0$ or $a=1$ a root lies on the unit circle; for $a<0$ a real root exceeds 1, and for $a>1$ the product of root magnitudes exceeds 1. Thus stability is exactly $0<a<1$.

At $a=1.5$, the undelayed pole is $-0.5$, but delayed poles have modulus $\sqrt{1.5}>1$. A nominally instantaneous transport with the wrong application phase can therefore be worse than a slower correctly phased one.

This is an illustrative controller, not a proof that CREBAIN's nonlinear bounded dynamics obey this model. It establishes why phase equivalence deserves a P0 test.

## 9.5 Deterministic direct/NCP equivalence

Assume the full state transition $F$ is deterministic for a fixed initial state, fixed random-generator state, declared inputs, and schedule. Assume an adapter preserves every semantically relevant input and invokes exactly the same transition once per step.

If direct and adapted states agree at $k$, their next inputs and transition agree, so their states agree at $k+1$. Since initial states agree, induction gives equality for all completed steps.

The assumptions expose the test obligations: no added delay, no missed availability, no changed saturation, no duplicated advance, no different random stream, and no hidden wall-clock input. Hash equality is useful evidence of selected byte identity, but not a proof that all relevant hidden state was included.

For approximate implementations, if $\|F(x)-F(y)\|\le L\|x-y\|$ and each step adds at most $\epsilon$ mismatch, then $e_{k+1}\le Le_k+\epsilon$. With $e_0=0$, induction yields $e_k\le\epsilon\sum_{i=0}^{k-1}L^i$. This can grow rapidly when $L>1$; an arbitrary per-step tolerance is not automatically a meaningful long-run trajectory guarantee.

## 9.6 Freshness on one receiver-owned clock

Let the body record a source event at $b_0$ and deadline $b_0+B$, with $B>0$. It accepts the returning command only when its current clock $b_a<b_0+B$. Then elapsed time on that clock satisfies $b_a-b_0<B$ by subtraction. No remote clock offset appears.

With 15 ms outbound delay and 15 ms return delay, a 20 ms source budget is expired at return. Restarting a 20 ms lifetime at the remote receiver after the outbound leg would incorrectly accept the same return. The grant avoids that reset.

Assumptions matter: the same body clock is monotonic over the interval, the source identity is exact, the original deadline is retained, and intermediate processing cannot forge a fresh source grant. Relating clock duration to physical elapsed time requires an oscillator/clock-error bound; no hard physical-time guarantee is claimed without one.

## 9.7 Closed-prefix consistency and at-most-once execution

Maintain counts $n$ for known neural commits, $p$ for known body commits, and $c$ for closed pairs. For one-in-flight coupling, require

$$
c\le p\le n,\qquad n-c\le1.
$$

Transitions preserve the inequalities: neural commit is allowed only from ready; body commit only after its neural commit; close only after both. Retirement permits no further same-generation transitions. This is a state-machine property, not distributed atomicity.

At-most-once mutation additionally needs a unique operation identity bound to semantic input, serialized ownership, retained/high-water state, and no transition from replay/unknown to fresh execution in the same generation. After a crash, this property may require retiring the generation rather than trying to reconstruct forgotten state.

The finite models in Appendix C explore bounded histories of these proposed rules. They do not model the real message parser, threads, process crashes, persistence implementation, or all possible histories.

## 9.8 Recording cannot evade conservation of backlog

Suppose a producer continues at rate $p$, a recorder drains at rate $c<p$, and retained buffer capacity is $B$. Backlog increases at rate $p-c$ and fills in at most $B/(p-c)$ after an empty start under the constant-rate model.

Therefore bounded memory, indefinite operation, lossless delivery, and a nonblocking producer cannot all be guaranteed against an arbitrarily slow recorder. Choose a profile-specific consequence: pause, reject/terminate, or drop and mark incompleteness.

A conditional fluid bound is also useful. If arrivals satisfy $\alpha(t)=b+rt$ and FIFO service provides $\beta(t)=C(t-T)^+$ with $b,r,T\ge0$ and $C>0$, $C\ge r$, then backlog is at most $b+rT$ and delay at most $T+b/C$. The latter follows because $C(t+b/C)=Ct+b\ge rt+b$. These bounds require the declared arrival and service envelopes; ordinary operating-system scheduling does not automatically supply them. Packetization and already-in-service storage need separate treatment.

## 9.9 Rate-code noise versus feedback window

Under an explicit independent Poisson assumption, $N\ge1$ neurons each firing at rate $\lambda>0$ over window $\Delta>0$ produce aggregate count $K\sim\mathrm{Poisson}(N\lambda\Delta)$. For $\hat\lambda=K/(N\Delta)$,

$$
\operatorname{Var}(\hat\lambda)=\frac{\lambda}{N\Delta},\qquad
CV=\frac{1}{\sqrt{N\lambda\Delta}}.
$$

At 20 Hz and a 20 ms window, the illustrative coefficient of variation is about 15.81% for 100 independent neurons and 55.90% for eight. These are model calculations, not measured NEST results. Correlation, refractory behavior, input structure, and readout filtering change the model.

Shorter windows reduce observation delay but increase noise under these assumptions. Extending a window changes the controller's information and phase; it is not a free protocol optimization. A very fast transport cannot remove that estimation tradeoff.

For equal marginal variance and pairwise correlation $\rho$, aggregate variance is multiplied by $1+(N-1)\rho$ relative to independence, when such a covariance model is valid. Thus increasing neuron count does not guarantee the independent-neuron reduction in noise.

## 9.10 Advisory authority is monotone

Let $A$ be the set of actions permitted by independently established policy and authority. Let $G$ be an advisory-derived restriction. Compose as $A'=A\cap G$. Then $A'\subseteq A$ by set intersection.

This simple property is the desired direction for Galadriel-to-Haldir influence. A monitor may remove permission or leave it unchanged; it must not mint a lease or expand $A$. The policy still decides how absence, staleness, and abstention affect $G$. This is monotonicity relative to independently granted $A$, not a claim that every restriction is irreversible over time. Restoration and latch reset require their own explicitly authorized policy. The finite powerset check establishes the set identity, not correctness of the real authorization implementation.

# 10. Performance claims and measurement design

## 10.1 Define the complete quantity

Measure source observation to actual body application, not merely controller computation:

$$
L_{loop}=L_{ingress}+L_{queue}+L_{map}+L_{neural}
+L_{readout}+L_{control}+L_{gate}+L_{return}+L_{apply}.
$$

Set $L_{gate}=0$ only in a profile without that dependency. Include observation generation when the question is sensor-to-effect rather than publication-to-effect. Instrumentation must state where every timestamp is taken.

The inspected `loop_latency_ms` timer ends before command submission and therefore does not measure this full chain. Existing performance documentation also distinguishes microbenchmarks from complete qualification. [S02], [S16]

## 10.2 Scale the problem before optimizing

Three entities with six observation doubles and three action doubles contain $3(6+3)8=216$ numeric bytes per step, or 10,800 bytes per second at 50 Hz. This excludes envelopes, neural outputs, evidence, and fan-out. It is an illustrative payload calculation, not observed traffic.

For that small case, allocator behavior, scheduling, repeated parsing, backend invocation, and semantic phase errors are plausible first targets. Large spike recordings or rich perception evidence can have completely different bandwidth needs and should not share an unbounded fast-path queue.

An initial local added-overhead goal of 1% of a 20 ms interval is 200 microseconds at a chosen tail percentile. This is a proposed target—not current performance, a forecast, or a hard real-time guarantee. Select hardware and load before adopting it as a release requirement.

## 10.3 Paired baseline methodology

Compare a direct test-only baseline and NCP-bound execution with identical model, controller, input schedule, seeds, CPU placement, and output interpretation. Randomize or alternate comparable runs to reduce time-dependent bias. Record instrumentation overhead.

Do not subtract unrelated p99 values and call the result p99 protocol overhead. Use stage measurements on the same execution or a justified paired design. Across hosts, use same-clock round-trip measurements unless clock synchronization error is measured and included in one-way uncertainty.

Report p50, p99, p99.9, maximum observed, sample count, warm-up policy, deadlines, rejected work, missed work, allocation count, copy volume, resident/retained memory, and throughput. Maximum observed is not a worst-case execution-time proof.

Drive the intended arrival schedule even during stalls, or explicitly count arrivals that the generator could not offer. A request generator that waits for every completion can hide overload by reducing offered load.

## 10.4 Qualification matrix

Run the selected workload with observer absent, normally active, deliberately slow, full, disconnected, and non-returning. Test multiple independent sessions and fairness. Separately test local transport, network transport, and gated mode rather than combining their numbers into one claim.

Record NEST build/model configuration, threads/MPI, machine and operating-system configuration, process placement, power policy where relevant, compiler options, binding versions, and exact package identities. Saturation or fail-closed behavior is part of the result, not an outlier to delete.

Do not pursue a claimed "zero overhead" result. The useful objective is a small, measured, bounded contribution that preserves the experiment's semantics.

# 11. What to simplify—and what not to oversell

The problematic "slop" is not that the repositories contain no implementation. It is the risk that terminology, architecture breadth, or assurance artifacts imply more than the executable integration establishes.

**Simplify names.** Distinguish version compatibility, exact prepared-contract agreement, local slot admission, publication, receiver admission, and application. A method returning success should name which of those occurred.

**Simplify contract ownership.** Maintain one normative semantic definition plus an executable cross-language boundary corpus. Generated schemas, prose, and validators must not independently invent expiry, missingness, or identity semantics. A hash of a schema does not capture unstated application behavior.

**Simplify the local profile.** One prepared role context, one backend owner, one outstanding step, and one retained outcome are enough for the initial deterministic loop. Do not force a local simulator through every remote physical-deployment mechanism.

**Do not simplify away authority.** When Haldir or a physical profile is selected, role separation and final-effect checks are real requirements. A local fast path must not silently become a weaker path under the same security label.

**Prefer executable evidence.** A small failing regression, a reproducible native loop, and a measured resource envelope are stronger evidence than additional review counts, broad "verified" labels, or speculative architecture diagrams. Negative results and explicit limitations should remain visible.

**Avoid fake universality.** NCP need not solve arbitrary multi-simulator co-simulation, distributed rollback, event-time causality, physical safety certification, and every information-theoretic analysis in its first useful local profile. Supporting a narrow correct use case is compatible with a clean extension boundary.

The design advances worth pursuing are specific: source-bound freshness with no relay reset; closed-prefix recovery rather than false atomicity; typed missingness that survives codecs; constant-work loss updates with exact declared semantics; and NCP-only role capabilities that cannot be bypassed by a convenient legacy adapter. Several foundations already exist in proposed NCP work. The contribution here is to make their failure cases and acceptance obligations concrete.

# Appendix C. Reproducible mathematical verification program

The complete program is included so the document stands alone. It requires Python 3.10 or later and only the standard library. Save the code as `verify_design.py` and run:

```sh
python3 verify_design.py --output verification_results.json
```

The program was executed with Python 3.13.5 for this report. It uses exact fractions for the principal arithmetic checks, floating-point roots for the illustrative stability sweep, and finite abstract state machines for ownership/retirement rules. It does not import or execute NCP, NEST, CREBAIN, Prisoma, Galadriel, or Haldir. Repeated invariant assertions are not independent experimental trials.

```python
#!/usr/bin/env python3
"""Executable mathematical checks for the NCP closed-loop design report.

Standard library only. These are exact-arithmetic property checks and small
abstract models, NOT tests of the Rust repositories, NEST, or a transport.
Run: python3 verify_design.py --output verification_results.json
Assertions use explicit exceptions so python -O cannot disable the checks.
"""
from __future__ import annotations

import argparse
import cmath
import itertools
import json
import math
import platform
from fractions import Fraction as F
from pathlib import Path
from typing import Any

COUNTS: dict[str, int] = {}
EXAMPLES: dict[str, Any] = {}


def check(group: str, predicate: bool) -> None:
    if not predicate:
        raise AssertionError(f"Property failed: {group}")
    COUNTS[group] = COUNTS.get(group, 0) + 1


def ceil_q(x: F) -> int:
    return -((-x.numerator) // x.denominator)


def strict_horizon(ttl: F, dt: F, cap: int) -> int:
    if ttl <= 0 or dt <= 0 or cap < 0:
        raise ValueError("positive times and nonnegative count cap required")
    return min(cap, max(0, ceil_q(ttl / dt) - 1))


def cusum_events(start: F, misses: int, reference: F) -> F:
    s = start
    for _ in range(misses):
        s = max(F(0), s + 1 - reference)
    return max(F(0), s - reference)


def cusum_closed(start: F, misses: int, reference: F) -> F:
    return max(F(0), start + misses * (1 - reference) - reference)


def rational_quantum(times: list[F]) -> F:
    if not times or any(x <= 0 for x in times):
        raise ValueError("positive nonempty time list required")
    denominator = math.lcm(*(x.denominator for x in times))
    integers = [x.numerator * (denominator // x.denominator) for x in times]
    return F(math.gcd(*integers), denominator)


def main(output: Path) -> None:
    # Independent oracle: explicitly enumerate all executable future positions.
    for tn, td, dn, dd, cap in itertools.product(
        range(1, 13), range(1, 5), range(1, 7), range(1, 4), (0, 1, 3, 10)
    ):
        ttl, dt = F(tn, td), F(dn, dd)
        expected = sum(j * dt < ttl for j in range(1, cap + 1))
        check("strict_horizon", strict_horizon(ttl, dt, cap) == expected)
    for ttl, dt in itertools.product(range(1, 101), range(1, 31)):
        check("integer_horizon", (ttl - 1) // dt == strict_horizon(F(ttl), F(dt), 1000))

    # Exact algebraic batching, including gaps greater than the current cap.
    for s, m, r in itertools.product(
        (F(0), F(1, 10), F(1), F(5)),
        (0, 1, 2, 3, 17, 255, 256, 257, 1000),
        (F(0), F(1, 20), F(1, 2), F(99, 100)),
    ):
        check("cusum_batch", cusum_events(s, m, r) == cusum_closed(s, m, r))
    s1 = cusum_closed(F(0), 3, F(1, 20))
    s2 = cusum_closed(s1, 3, F(1, 20))
    check("decimation_counterexample", s1 == F(14, 5) and s2 == F(28, 5) and s2 >= 5)
    full = cusum_closed(F(0), 1000, F(1, 20))
    capped = cusum_closed(F(0), 256, F(1, 20))
    check("gap_cap_counterexample", capped < 300 < full)
    EXAMPLES["cusum"] = {
        "decimated_consumption": [float(s1), float(s2)],
        "gap_1000_exact": float(full), "gap_256_capped": float(capped),
        "threshold": 300,
    }

    # Small but strictly positive valid binary64 span: EPSILON is not a scale.
    span = 2.0 ** -60
    epsilon = 2.0 ** -52
    old_output = 0.0 if abs(span) < epsilon else 200.0 * (span / span)
    mathematical_output = 200.0 * (span / span)
    check("small_span_counterexample", span > 0 and old_output == 0 and mathematical_output == 200)
    EXAMPLES["small_span"] = {"span": span, "epsilon": epsilon,
                              "old_output": old_output, "required_endpoint": mathematical_output}

    # A live object moved between threads need not retain a thread-local origin.
    absolute_t1, origin_a, absolute_t2, origin_b = F(100), F(0), F(101), F(100)
    check("thread_origin_counterexample", absolute_t2 > absolute_t1 and
          absolute_t2 - origin_b < absolute_t1 - origin_a)
    EXAMPLES["thread_origin"] = {"absolute_samples": [100, 101],
                                 "thread_local_elapsed_samples": [100, 1]}

    # Rational common tick construction and exact accumulated position.
    pool = (F(1, 10000), F(1, 1000), F(1, 100), F(1, 50), F(1, 60), F(1, 30))
    for pair in itertools.combinations(pool, 2):
        q = rational_quantum(list(pair))
        ticks = [x / q for x in pair]
        check("rational_timebase", all(t.denominator == 1 for t in ticks))
        check("rational_timebase", math.gcd(*(t.numerator for t in ticks)) == 1)
    q = rational_quantum([F(1, 10000), F(1, 50)])
    check("rational_timebase", 1_000_000 * 200 * q == F(20000))
    EXAMPLES["timebase"] = {"quantum_seconds": str(q), "ticks_per_20ms": 200}

    # A one-step transport phase error can change stability even at zero RTT.
    stable_now, stable_delayed = [], []
    for n in range(-10, 31):
        a = n / 10.0
        immediate = abs(1 - a) < 1 - 1e-10
        root = cmath.sqrt(1 - 4 * a)
        delayed = max(abs((1 + root) / 2), abs((1 - root) / 2)) < 1 - 1e-10
        check("delay_stability", immediate == (0 < a < 2))
        check("delay_stability", delayed == (0 < a < 1))
        if immediate:
            stable_now.append(a)
        if delayed:
            stable_delayed.append(a)
    check("delay_stability", F(3, 2) > 1 and abs(1 - F(3, 2)) < 1)
    EXAMPLES["delay_stability"] = {"a": 1.5, "no_delay_pole": -0.5,
                                   "one_step_delay_pole_modulus": math.sqrt(1.5)}

    # Body-originated grant checks: total elapsed round trip, no relay renewal.
    for outbound, computation, inbound, budget in itertools.product(
        range(8), range(8), range(8), range(1, 12)
    ):
        sampled_at = 100
        application = sampled_at + outbound + computation + inbound
        deadline = sampled_at + budget
        accepted = application < deadline
        check("source_grant", accepted == (outbound + computation + inbound < budget))
    check("freshness_counterexample", 100 + 15 + 15 >= 100 + 20 and 115 + 15 < 115 + 20)
    EXAMPLES["freshness"] = {"budget_ms": 20, "outbound_ms": 15,
                              "return_ms": 15, "source_grant_accepts": False,
                              "receiver_restarted_ttl_accepts": True}

    # Finite deterministic equivalence example; wall pacing is not model input.
    def transition(state: tuple[F, F], obs: F) -> tuple[tuple[F, F], F]:
        plant, neural = state
        neural_next = neural / 2 + obs / 4
        action = -neural_next
        return (plant + action / 10, neural_next), action
    direct, adapted = (F(1), F(0)), (F(1), F(0))
    for step in range(200):
        direct, action_d = transition(direct, direct[0])
        payload = (step, str(adapted[0]))
        decoded_observation = F(payload[1])
        adapted, action_a = transition(adapted, decoded_observation)
        check("deterministic_equivalence_model", direct == adapted and action_d == action_a)

    # Paired advancement: a tiny state model, not an implementation proof.
    events = ("neural_commit", "plant_commit", "close", "uncertain", "restart")
    for history in itertools.product(events, repeat=5):
        phase, retired = "ready", False
        neural_count = plant_count = closed_count = 0
        frozen = None
        for event in history:
            if retired:
                # Same-generation restart never reactivates this object.
                check("paired_prefix_model", frozen ==
                      (phase, neural_count, plant_count, closed_count))
                continue
            if event == "uncertain":
                retired = True
                frozen = (phase, neural_count, plant_count, closed_count)
            elif event == "neural_commit" and phase == "ready":
                neural_count += 1
                phase = "neural"
            elif event == "plant_commit" and phase == "neural":
                plant_count += 1
                phase = "plant"
            elif event == "close" and phase == "plant":
                closed_count += 1
                phase = "ready"
            check("paired_prefix_model", closed_count <= plant_count <= neural_count)
            check("paired_prefix_model", neural_count - closed_count <= 1)
        if retired:
            check("paired_prefix_model", frozen ==
                  (phase, neural_count, plant_count, closed_count))

    # Finite abstract operation owner: retained result + high water after ACK.
    events = ("new", "retry", "commit", "ack", "uncertain")
    for history in itertools.product(events, repeat=6):
        state, executions, committed, highwater = "empty", 0, False, 0
        for event in history:
            if event == "new" and state == "empty" and highwater == 0:
                state, executions = "pending", executions + 1
            elif event == "commit" and state == "pending":
                state, committed, highwater = "retained", True, 1
            elif event == "ack" and state == "retained":
                state = "acknowledged"
            elif event == "uncertain" and state == "pending":
                state = "retired"
            # 'retry' only replays/returns pending/unknown; never executes.
            check("at_most_once_model", executions <= 1)
            check("at_most_once_model", not committed or highwater == 1)

    # Innovation quadratic form: exact 2x2 Cholesky example, not calibration.
    # L=[[2,0],[1,3]], S=L*L^T=[[4,2],[2,10]], det(S)=36.
    for r0, r1 in itertools.product(range(-5, 6), repeat=2):
        v0 = F(r0, 2)
        v1 = (F(r1) - v0) / 3
        direct_q = F(10*r0*r0 - 4*r0*r1 + 4*r1*r1, 36)
        check("innovation_quadratic", direct_q == v0*v0 + v1*v1)
        check("innovation_quadratic", direct_q >= 0)

    # Exact recurrence at its error bound, including L=0 and L=1.
    for lip in (F(0), F(1, 2), F(1), F(6, 5)):
        error, eps = F(0), F(1, 100)
        for k in range(1, 31):
            error = lip * error + eps
            bound = eps * sum((lip**i for i in range(k)), F(0))
            check("error_propagation", error == bound)

    # Equal marginal variance: explicitly sum all covariance entries.
    for n, rho in itertools.product(range(2, 21), (F(0), F(1, 10), F(1, 2))):
        total = sum((F(1) if i == j else rho
                     for i in range(n) for j in range(n)), F(0))
        check("correlated_count_variance", total == n * (1 + (n-1)*rho))

    # An advisory restriction can only shrink independently granted permission.
    universe = set(range(5))
    subsets = [{i for i in universe if bits & (1 << i)} for bits in range(32)]
    for base, advisory in itertools.product(subsets, repeat=2):
        check("authority_monotonicity", (base & advisory) <= base)

    # Fluid arrival/service envelope, conditional on c>=r and FIFO service.
    for burst, rate, capacity, latency in itertools.product(
        (F(1), F(3)), (F(0), F(1), F(2)), (F(2), F(4)), (F(0), F(1), F(3))
    ):
        if capacity < rate:
            continue
        delay_bound = latency + burst / capacity
        backlog_bound = burst + rate * latency
        for i in range(101):
            t = F(i, 10)
            alpha = burst + rate * t
            beta = capacity * max(F(0), t - latency)
            check("queue_envelope_model", alpha - beta <= backlog_bound)
            service_shifted = capacity * max(F(0), t + delay_bound - latency)
            check("queue_envelope_model", service_shifted >= alpha)

    # Poisson assumptions are explicit; these are formulas, not observed spikes.
    for neurons in (8, 100):
        rate, window = F(20), F(1, 50)
        expected_count = neurons * rate * window
        variance_rate_estimate = rate / (neurons * window)
        check("poisson_rate_formula", variance_rate_estimate / rate ** 2 == 1 / expected_count)
    EXAMPLES["poisson_cv"] = {"N100_r20_window20ms": 1 / math.sqrt(40),
                               "N8_r20_window20ms": 1 / math.sqrt(3.2)}
    check("payload_arithmetic", 3 * (6 + 3) * 8 == 216)
    check("payload_arithmetic", 216 * 50 == 10800)
    check("payload_arithmetic", 64 * 1024 * 1024 == 67108864)
    check("payload_arithmetic", F(20, 1000) / 100 == F(200, 1000000))

    result = {
        "status": "PASS",
        "scope": "Exact-arithmetic checks, numerical examples, and abstract finite models only; no repository or NEST execution.",
        "python": platform.python_version(),
        "group_count": len(COUNTS),
        "assertion_count": sum(COUNTS.values()),
        "groups": COUNTS,
        "examples": EXAMPLES,
    }
    output.parent.mkdir(parents=True, exist_ok=True)
    output.write_text(json.dumps(result, indent=2) + "\n", encoding="utf-8")
    print(json.dumps({k: result[k] for k in ("status", "group_count", "assertion_count", "scope")}, indent=2))


if __name__ == "__main__":
    parser = argparse.ArgumentParser(description=__doc__)
    parser.add_argument("--output", type=Path, default=Path("verification_results.json"))
    args = parser.parse_args()
    main(args.output)
```
