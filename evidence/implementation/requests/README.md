# B01 review requests

This directory stores deterministic request artifacts for external B01 review.
The artifacts allocate unfilled slots. They do not record or authorize human decisions.

The current generated artifact is
[`B01/review-request.v1.json`](B01/review-request.v1.json).
The generator is
[`scripts/generate_b01_review_request.py`](../../../scripts/generate_b01_review_request.py).

## Generate the request

Run this command from the repository root:

```text
python3 scripts/generate_b01_review_request.py \
  --commit 3661d01c20445f84004e6f89bfa3aa9e85fe3a7f \
  --authorized-ref refs/remotes/origin/main \
  --self-test \
  --write
```

Configure `origin` with exactly one of these fetch URLs:

- `git@github.com:sepahead/NCP.git`
- `https://github.com/sepahead/NCP.git`

The generator rejects all other origin URLs.
This rule rejects credential-bearing HTTPS URLs.

The command reads bound blobs from the specified Git commit.
The authorized ref is fixed at `refs/remotes/origin/main`.
The local branch is fixed at `refs/heads/main`.

The generator queries the canonical SSH URL with the current user's agent.
The query uses `git ls-remote --exit-code --refs` for `refs/heads/main`.
The query pins GitHub's Ed25519 host key and disables interactive credentials.
The query has a 15-second timeout.
The pin matches [GitHub's published SSH fingerprints](https://docs.github.com/en/authentication/keeping-your-account-and-data-secure/githubs-ssh-key-fingerprints).
Pin updates are deliberate and fail closed until the checked profile changes.

The observed remote commit must equal both fixed local refs.
The packet commit must be an ancestor of that commit.
The commit must retain the exact `CURRENT` zero-review packet subject.
The commit must retain the same decision set, source cut, and review policy.

The request binds an ordered two-file generator roster.
The roster names the request generator first and its immutable Git helper second.
The ledger checker reopens both files from the retained issuance commit.
It also requires the current files to match those exact bytes.

The request records the retained issuance commit and tree.
The request also records a normalized remote-observation identity.
The identity contains no configured credential or local absolute path.
SSH and HTTPS origin configurations produce identical request bytes.

The command does not change the checked-out packet or registry.
Do not edit the generated JSON manually.

## Check the request

Run this command from the repository root:

```text
python3 scripts/generate_b01_review_request.py \
  --commit 3661d01c20445f84004e6f89bfa3aa9e85fe3a7f \
  --authorized-ref refs/remotes/origin/main \
  --self-test \
  --check
```

The default check is hermetic.
It does not query the network or require a local `main` branch.
It resolves the literal checked-out `HEAD` commit.
The retained issuance commit must be an ancestor of `HEAD`.
The checked-out commit must retain the exact packet and registry bytes.
The check fails for missing, changed, or symbolic-link output.

The current commit can descend from the retained issuance commit.
Unrelated descendant commits do not change the generated bytes.
The exact packet and decision-set bytes must remain current.

History divergence or non-descendance fails closed.
Packet supersession, review records, or subject drift also fails closed.
The self-test rejects authority fields, changed bindings, and malformed slot rosters.
It also rejects replacement refs, grafts, shallow history, and malformed Git objects.

The generator joins the closure status to exact source-cut artifact identities.
It derives the 33 case and 289 mutation counts from the bound corpus bytes.
It derives the eight deferral counts from the bound closure-source bytes.
These joins prove identity and count coherence only.
They do not execute the Rust or TypeScript semantic engines.
They do not independently prove semantic closure or accept an ADR.

Run the live check from a synchronized canonical `main` checkout:

```text
python3 scripts/generate_b01_review_request.py \
  --commit 3661d01c20445f84004e6f89bfa3aa9e85fe3a7f \
  --authorized-ref refs/remotes/origin/main \
  --self-test \
  --live-check
```

The live check queries canonical remote `main`.
It requires both fixed local refs to equal that observation.
Network failure, ref deletion, divergence, or remote movement fails closed.
The observation describes that bounded check interval.
It does not promise continuous branch currentness after the command exits.

Atomic request installation binds the final observed file and directory identities.
The output directory requires one trusted owner and no group or world write access.
Callers must provide one exclusive or cooperating writer during installation.
Portable path replacement cannot exclude uncooperative same-user or root mutation.
Such mutation after the final rejoin is outside the instantaneous emission claim.

## Fixed minimum roster

The request contains these minimum counts:

- 11 ADR decisions.
- 52 role obligations.
- 53 distinct-identity slots.
- 5 independent obligations.
- 6 independent-identity slots.
- 112 evidence requirements.

Each identity slot requires one role authorization and one external review receipt.
Each independent slot also requires one independence assessment.
All slots and evidence requirements have the `UNFILLED` state.

## Authority boundary

The generator does not authenticate reviewers.
It does not verify role authorization, independence, or external receipts.
It does not accept an ADR or change a task state.
It does not change the review packet or its decision-set digest.
The remote observation supplies issuance currentness evidence only.
It does not authenticate a reviewer or repository owner.
It does not prove branch protection, commit signing, or remote ownership.
The retained identity does not attest historical remote state.
It grants no review, role, protocol, task, or release authority.

Only human reviewers can populate review decisions.
Humans or authenticated non-model systems can populate review evidence separately.
Put that evidence under `evidence/implementation/reviews/B01/`.
Conditional or superseding evidence is additional and is not preallocated.
