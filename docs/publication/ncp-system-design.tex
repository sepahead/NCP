\begin{abstract}
\noindent NCP (Neuro-Cybernetic Protocol) connects independently owned simulations,
bodies, sensors, and analysis tools through exact, bounded data contracts. This report
describes NCP in three scopes. The modular local SDK is implemented twice, in Rust and
in Python. It retains each outcome until an exact acknowledgement. It moves payloads in bounded
chunks, and it checks the digest of each chunk and of each complete payload. Selected installed campaigns observed it. A fixed-role local
profile serves as a regression control. The broader \texttt{1.0.0-rc.1} candidate runs
wire \texttt{1.0} today, and a proposed architecture closes its known gaps. That
architecture separates four traffic planes, admits each frame through ordered gates,
and bounds every retained byte.

The report derives each interface and resource equation from named assumptions. A
Lean~4 file checks the discrete arithmetic. The equations are design accounting, not
measurements. No part of NCP is released. Local tests, equations, and figures cannot
establish live security, physical safety, controller stability, or scientific validity.
\end{abstract}

\section{Scope and reading rules}

\subsection{What NCP does}

NCP is a contract layer between separate programs. It defines message identity, the
correlation of one request with one outcome, acknowledgement, and the lifetime of byte
buffers. Each program keeps its own state, physics, models, and decisions. NCP runs no
central process.

Figure~\ref{fig:system-map} shows the implemented modular composition. A host program
selects the applications, installs their exact contracts, and connects each application
through NCP. The applications in the figure are the current ecosystem projects. Engram
hosts a network in NEST, a simulator for spiking neural networks. CREBAIN simulates
bodies and sensors. Prisoma captures exchanges and orders experiments. Galadriel checks
sensor consistency.

\section{Modular exchange}

\NcpStatus{implemented}
Rust and Python implement this contract independently. The owners are
\path{ncp-core/src/modular_owner.rs} and \path{local/python/ncp_local/modular_owner.py}.
Their shared descriptor is \path{ncp-core/src/modular_profile.v1.json}.

\subsection{Installed application boundary}

The host selects an application before it opens a channel. The application supplies
closed types for preparation, commands, imports, metadata, finish, and results. It
also supplies validators and its exact descriptor. Each message binds the digests of
the core descriptor and the application descriptor.

A request cannot install a schema, load a module, select an executable, or open a
path that a peer selects. The execution interface accepts no method string with an
arbitrary JSON value. An unknown application identity fails admission.

\subsection{Request identity}

Each request names a binding, a sequence number, a closed operation, and the complete
typed digest. The binding names the profile, application, run, endpoint, and
generation. The sequence number $s$ satisfies
\begin{equation}\label{eq:sequence-domain}
s\in\{1,2,\ldots,\hat s\},\qquad \hat s=2^{53}-1=9{,}007{,}199{,}254{,}740{,}991.
\end{equation}
The bound $\hat s$ is the largest integer $n$ for which binary64 represents both $n$
and $n+1$ exactly. Every integer from 0 to $2^{53}$ is exact in binary64, and every
larger integer parses to at least $2^{53}$. A
reader that parses numbers as binary64 therefore keeps each valid $s$ exact and still
detects an out-of-range value. The codec rejects \texttt{-0}, fractions, booleans, and
larger integers.

Let $r_s$ be the retained outcome bytes of request $s$. The first request has no
predecessor. Every later request must name the digest of the last admitted outcome:
\begin{equation}\label{eq:predecessor}
\operatorname{pred}(s+1)=\Hash(r_s).
\end{equation}
Queries and acknowledgements do not change the predecessor.

\subsection{Owner steps}

Figure~\ref{fig:exchange} shows the order of owner work. The owner checks for an exact
duplicate before it reads mutable application state. The first execution can change
the state that admitted it, so a later state check could reject a valid retry.

\NcpFigure{exchange}{The modular exchange. An exact duplicate
returns the retained bytes. Admission changes nothing. Reservation precedes the use of
the sequence number. The acknowledgement frees only the result frame.\label{fig:exchange}}

Admission is pure: it reads state and returns the demanded inputs and outputs. It
performs no I/O, external reservation, or backend mutation. The core then resolves each
input and allocates each output. Only after that step does it consume $s$ and assign
buffer identifiers.

A backend error, panic, invalid result, or incomplete output after entry consumes $s$.
The owner retains a bounded indeterminate result when possible and retires the
generation. It never converts that outcome into success or into a clean rejection.

Before commit, the owner decodes the staged response with the installed output codec.
The decoded value must reproduce the complete typed digest. This check rejects a
non-finite value that a codec turns into \texttt{null}, and it rejects signed-zero
normalization.

\subsection{Worked example}

Preparation at $s=1$ produces outcome $r_1$. After the client acknowledges $r_1$, it
sends $s=2$ with predecessor $\Hash(r_1)$. Suppose admission rejects the input of
request~2. The rejection leaves $s=2$ unused and keeps the predecessor $\Hash(r_1)$.
The client can send corrected input as $s=2$ without an acknowledgement of the
rejection. A conflict, an unavailable result, or a mismatched response cannot use this
path.

\subsection{Uncertain dispatch}

End of stream, partial framing, a timeout, or a failed read or write retires the
channel. A lost acknowledgement keeps the pending evidence. The client stops the
channel and never retries or reconnects on its own. A query can read the original
retained bytes by sequence number and request digest.

\section{Bounded payloads and logical capacity}

\NcpStatus{implemented}
The payload primitives are \path{ncp-core/src/modular_buffer.rs} and
\path{local/python/ncp_local/modular_buffer.py}.

\subsection{Chunked transfer}

A payload is one sealed byte string of length $\ell$ with $1\leq\ell\leq\hat\ell$ and
$\hat\ell=8{,}388{,}608$ bytes. A chunk carries at most $\hat\ell_c=32{,}768$ decoded
bytes. The chunk count is
\begin{equation}\label{eq:chunk-count}
m=\left\lceil\frac{\ell}{\hat\ell_c}\right\rceil.
\end{equation}
Chunk $j$, for $0\leq j<m$, starts at byte $j\hat\ell_c$ and has length
\begin{equation}\label{eq:chunk-length}
\ell_j=\min\bigl(\hat\ell_c,\ \ell-j\hat\ell_c\bigr).
\end{equation}

\begin{derivation}[Chunks tile the payload]
Equation~\eqref{eq:chunk-count} gives $(m-1)\hat\ell_c<\ell\leq m\hat\ell_c$. For
$j\leq m-1$, the start satisfies $j\hat\ell_c\leq(m-1)\hat\ell_c<\ell$, so
$\ell_j\geq1$. Every chunk before the last has length $\hat\ell_c$. The last chunk has
length $\ell-(m-1)\hat\ell_c$. The lengths therefore sum to $\ell$ with no gap or
overlap. The payload bound gives
\begin{equation}\label{eq:chunk-max}
m\leq\left\lceil\frac{\hat\ell}{\hat\ell_c}\right\rceil=256.
\end{equation}
\end{derivation}

Figure~\ref{fig:payload-transfer} shows the transfer. The receiver reserves all $\ell$
bytes before it accepts the first chunk. It admits only the next contiguous chunk. Each
chunk must match its index, offset, decoded length, canonical base64 spelling, and
SHA-256 digest. The seal then checks the SHA-256 digest of the complete payload. Valid
chunk digests cannot replace that check. A failed admission keeps counters,
reservations, and stored bytes unchanged.

\NcpFigure{payload-transfer}{Bounded payload transfer. The
receiver reserves the full length first. The seal checks the complete
digest.\label{fig:payload-transfer}}

An acknowledgement releases the retained result frame only. Buffer release and import
abort are separate operations on one exact named entry.

\subsection{Sensor clock arithmetic}

The CREBAIN body advances at $f_b=120$ ticks per second. Its acoustic model produces
$f_a=16{,}000$ samples per second. For body tick $k\geq1$, the pressure samples have the
index interval
\begin{equation}\label{eq:sample-interval}
I_k=\left[\left\lfloor\frac{(k-1)f_a}{f_b}\right\rfloor,\
\left\lfloor\frac{kf_a}{f_b}\right\rfloor\right).
\end{equation}
The ratio $f_a/f_b=400/3$ is not an integer. The first three ticks contain 133, 133, and
134 samples. For every $u\in\mathbb{N}$,
\begin{equation}\label{eq:sample-group}
\sum_{k=3u+1}^{3u+3}\#I_k
=\left\lfloor\frac{(3u+3)\cdot400}{3}\right\rfloor-\left\lfloor\frac{3u\cdot400}{3}\right\rfloor
=400.
\end{equation}
Each group of three ticks therefore holds exactly 400 samples and spans 25 ms of
simulated time. The endpoints are sample indices, not timestamps. The CREBAIN contract
\texttt{crebain.sensor-pressure.v1} stores each sample as one 8-byte little-endian
binary64 value in pascals.

Two retained campaigns in Table~\ref{tab:campaigns} match this partition. The sensor
transfer counted 3,200 pressure samples in 24 body ticks, which is eight groups of 400.
The city maximum batch recorded the intervals $[0,133)$, $[133,266)$, and $[266,400)$
for ticks 1 to 3. Its third tick is 32 bytes larger, because each of four microphones
carries one more sample.

\subsection{Neural coupling arithmetic}

The example policy advances NEST once per three body ticks, with step
$\Delta_n=25{,}000\,\mu\mathrm{s}$ and recording delay $\delta=1{,}000\,\mu\mathrm{s}$.
For an executed end time $t_e$, the complete spike window is $(\tau_0,\tau_1]$ with
\begin{equation}\label{eq:spike-window}
\tau_0=\max(0,\ t_e-\Delta_n-\delta),\qquad \tau_1=t_e-\delta.
\end{equation}
All times are integer microseconds. For $t_e\geq\Delta_n$ and $\delta<\Delta_n$, the
window is nonempty: $\tau_1-\tau_0=\min(t_e-\delta,\ \Delta_n)>0$. For $n_{\mathrm{ne}}$
neurons and $n_{\mathrm{sp}}$ spikes in the window, the mean rate for each neuron is
\begin{equation}\label{eq:spike-rate}
\mathrm{rate}=\frac{n_{\mathrm{sp}}\cdot10^{6}}{n_{\mathrm{ne}}(\tau_1-\tau_0)}\
\mathrm{Hz}.
\end{equation}
A complete zero count is observed silence. A pending window supplies no count and no
rate. This discrete policy tests interface causality. It makes no learned-control claim.

A plan has one to three entities and at most 1,024 coupled steps. A step lasts
1,000 to 1,000,000~$\mu$s in multiples of 1,000~$\mu$s. A frame is a 4-byte big-endian

Capture reservation precedes neural and body mutation. A lost response does not show

\subsection{Ordered gates}

Figure~\ref{fig:overview} shows the gates with the numbers 1 to 6. Let $f$ be one
received frame and $\gamma_j(f)$ the Boolean result of gate $j$:
\begin{equation}\label{eq:gate-set}
(\gamma_1,\ldots,\gamma_6)=(\gamma_{\mathrm{raw}},\gamma_{\mathrm{principal}},
\gamma_{\mathrm{wire}},\gamma_{\mathrm{session}},\gamma_{\mathrm{typed}},
\gamma_{\mathrm{effect}}).
\end{equation}
Gates 1 to 5 are shared. For a non-action frame, $\gamma_{\mathrm{effect}}(f)$ is true
by definition. For an action frame, it is body-owned admission at the effect boundary.
A frame is admitted only when every gate is true:
\begin{equation}\label{eq:admission}
\Gamma(f)=\bigwedge_{j=1}^{6}\gamma_j(f).
\end{equation}

\NcpFigure{overview}{Five shared gates run in order. Action
frames add the body effect gate.\label{fig:overview}}

The receiver does not evaluate equation~\eqref{eq:admission} as an unordered set. It
evaluates the prefixes
\begin{equation}\label{eq:admission-prefix}
\Gamma_0(f)=\mathrm{true},\qquad
\Gamma_j(f)=\Gamma_{j-1}(f)\land\gamma_j(f),\quad 1\leq j\leq6,
\end{equation}
and runs gate $j$ only when $\Gamma_{j-1}(f)$ is true.

\begin{derivation}[First failure decides]
Suppose the ordered evaluation meets a false gate. Let $j^\ast$ be the first index with
$\gamma_{j^\ast}(f)=\mathrm{false}$. Then $\Gamma_{j^\ast-1}(f)=\mathrm{true}$ and
$\Gamma_{j^\ast}(f)=\mathrm{false}$. No gate after $j^\ast$ runs. The rejection class
of gate $j^\ast$ is the result. The receiver emits no diagnostic that depends on an
unbounded or unauthenticated later field.
\end{derivation}

\section{Prepared runtime and hot-path latency}

\NcpStatus{proposed}

Preparation validates deployment input once. It compiles immutable handles and
reserves shared state before any publisher, subscription, callback, or actuator
resource exists. Figure~\ref{fig:runtime} shows the six stages of each later frame.

\NcpFigure{runtime}{Prepared runtime. One short owner step
admits each frame. External work runs outside the lock.\label{fig:runtime}}

\subsection{Stage times}

Let the ordered stages be
\begin{equation}\label{eq:stages}
\mathcal{I}=(\mathrm{bound},\mathrm{verify},\mathrm{decode},\mathrm{locate},
\mathrm{admit},\mathrm{handoff}).
\end{equation}
For stage $i\in\mathcal{I}$, let $t_i^{\mathrm{in}}$ and $t_i^{\mathrm{out}}$ be ticks
of one receiver clock incarnation. The stage time is
\begin{equation}\label{eq:stage-time}
T_i=t_i^{\mathrm{out}}-t_i^{\mathrm{in}}\geq0.
\end{equation}
The accounting boundaries are contiguous: $t_i^{\mathrm{out}}$ equals
$t_{i'}^{\mathrm{in}}$ for the next stage $i'$. This equality is an accounting rule. It
does not require a thread or process boundary. Every inner tick then occurs once with
each sign, and the sum telescopes:
\begin{equation}\label{eq:hot-time}
T_{\mathrm{hot}}=t_{\mathrm{handoff}}^{\mathrm{out}}-t_{\mathrm{bound}}^{\mathrm{in}}
=\sum_{i\in\mathcal{I}}T_i.
\end{equation}
If a profile selects a finite ceiling $\hat T_i$ with $0\leq T_i\leq\hat T_i$, then
\begin{equation}\label{eq:hot-bound}
T_{\mathrm{hot}}\leq\sum_{i\in\mathcal{I}}\hat T_i=\hat T_{\mathrm{hot}}.
\end{equation}
Transport delay comes before $t_{\mathrm{bound}}^{\mathrm{in}}$. Queue, application, and
device time come after $t_{\mathrm{handoff}}^{\mathrm{out}}$. None of them is part of
$T_{\mathrm{hot}}$. A later measurement must show that the implementation meets each
$\hat T_i$ on the qualified platform.

\subsection{Allocations and copies}

Let $n_{\mathrm{alloc},i}$ be the number of heap allocations and $n_{\mathrm{copy},i}$
the number of full-payload copies in stage $i$ after preparation. The totals are
\begin{equation}\label{eq:alloc-copy}
n_{\mathrm{alloc}}=\sum_{i\in\mathcal{I}}n_{\mathrm{alloc},i},\qquad
n_{\mathrm{copy}}=\sum_{i\in\mathcal{I}}n_{\mathrm{copy},i}.
\end{equation}
For a fixed-layout frame in a contiguous receive buffer, the target is
$n_{\mathrm{alloc}}=0$ and $n_{\mathrm{copy}}=0$. A segmented receive can need one
bounded flattening copy. If preparation reserved that buffer, $n_{\mathrm{alloc}}=0$ and
$n_{\mathrm{copy}}\leq1$. These are targets, not current measurements.

\section{Finite memory and queue isolation}

\NcpStatus{proposed}

\subsection{Lifecycle stores}

Let $\mathcal{S}=\{\mathrm{ses},\mathrm{ctx},\mathrm{res},\mathrm{wait}\}$ name the
session slots, prepared contexts, retained results, and optional waiters. Store
$\kappa\in\mathcal{S}$ holds at most $\hat n_\kappa$ units. One unit is charged at most
$\hat b_\kappa$ bytes, which cover content, backing storage, index entries, and
metadata. The fixed owner overhead is $\hat b_0$ bytes. The bytes $M_\kappa$ that store
$\kappa$ retains then satisfy
\begin{equation}\label{eq:store-bound}
M_\kappa\leq\hat n_\kappa\hat b_\kappa,
\end{equation}
because units times bytes per unit gives bytes. The stores are disjoint accounting
domains, so
\begin{equation}\label{eq:lifecycle-memory}
M_{\mathrm{life}}\leq\hat b_0+\sum_{\kappa\in\mathcal{S}}\hat n_\kappa\hat b_\kappa.
\end{equation}
With waiters off, $\hat n_{\mathrm{wait}}=0$, but $\hat b_0$ stays. An empty
preallocated table does not cost zero bytes.

Fix one order $(\kappa_1,\ldots,\kappa_4)$ of $\mathcal{S}$. The receiver computes each
product and then the partial sums
\begin{equation}\label{eq:partial-sums}
\sigma_u=\hat b_0+\sum_{v=1}^{u}\hat n_{\kappa_v}\hat b_{\kappa_v},\qquad 1\leq u\leq4,
\end{equation}
with checked arithmetic. An undefined product or sum rejects the profile before any
allocation.

Portable bytes do not bound the heap of every language runtime. Each store therefore
also has a finite, monotone local charge $J_\kappa(\hat n_\kappa)$ in one runtime unit,
with fixed charge $J_0$:
\begin{equation}\label{eq:local-charge}
J_{\mathrm{life}}\leq J_0+\sum_{\kappa\in\mathcal{S}}J_\kappa(\hat n_\kappa).
\end{equation}
The receiver admits a profile only when both bounds hold.

\subsection{Plane queues}

Let $\mathcal{Q}=\{\mathrm{ctl},\mathrm{per},\mathrm{act},\mathrm{obs},\mathrm{ext}\}$
name the control, perception, action, observation, and extension queues. Queue
$q\in\mathcal{Q}$ holds $n_q$ items with $0\leq n_q\leq\hat n_q$ and $\hat n_q\geq1$.
Its items $b_{q,1},\ldots,b_{q,n_q}$ retain
\begin{equation}\label{eq:queue-bytes}
S_q=\sum_{k=1}^{n_q}|b_{q,k}|\leq\hat S_q
\end{equation}
bytes. Each item also carries at most $\mu_q$ metadata bytes. The visible-loss count
satisfies $0\leq g_q\leq\hat g_q$, where $\hat g_q\leq W$ is the largest representable
count.

Figure~\ref{fig:queue-admission} shows admission of a new item $b$. The plane policy
either rejects $b$ or selects one allowed victim set
$X_q(b)\subseteq\{1,\ldots,n_q\}$. Control and extension select no victim. Perception
can replace the latest replaceable item. Observation selects the oldest items. Action
selects only work that its severity order permits it to displace. Define
\begin{equation}\label{eq:victims}
e_q=\#X_q(b),\qquad R_q=\sum_{k\in X_q(b)}|b_{q,k}|.
\end{equation}

\NcpFigure{queue-admission}{Plane queue admission. Count and
byte limits both apply before any byte is retained.\label{fig:queue-admission}}

The subset relation gives $0\leq e_q\leq n_q$ and $0\leq R_q\leq S_q$. Admission
requires
\begin{equation}\label{eq:queue-admit}
n_q-e_q+1\leq\hat n_q,\qquad S_q-R_q+|b|\leq\hat S_q,\qquad
g_q+e_q\leq\hat g_q.
\end{equation}
If no allowed victim set satisfies the first two conditions, the owner rejects $b$ and
leaves the queue unchanged. The owner computes the third sum as $\cadd(g_q,e_q)$. If
the loss count cannot advance, the owner seals the affected stream and leaves the
queue unchanged. Otherwise one atomic owner step records the loss, removes the
victims, and installs $b$. The new state is
\begin{equation}\label{eq:queue-after}
n_q'=n_q-e_q+1\leq\hat n_q,\qquad S_q'=S_q-R_q+|b|\leq\hat S_q,\qquad
g_q'=g_q+e_q\leq\hat g_q.
\end{equation}
A count limit alone is not enough, because item sizes vary. With fixed queue overhead
$\hat b_{Q,0}$, the portable queue envelope is
\begin{equation}\label{eq:queue-envelope}
M_{\mathrm{queues}}\leq\hat b_{Q,0}+\sum_{q\in\mathcal{Q}}
\bigl(\hat S_q+\hat n_q\mu_q\bigr).
\end{equation}
Stores and queues are disjoint domains. Their prepared total is
\begin{equation}\label{eq:prepared-memory}
M_{\mathrm{prep}}\leq\hat b_0+\sum_{\kappa\in\mathcal{S}}\hat n_\kappa\hat b_\kappa
+\hat b_{Q,0}+\sum_{q\in\mathcal{Q}}\bigl(\hat S_q+\hat n_q\mu_q\bigr).
\end{equation}
Each queue also has a finite local charge $J_q(\hat n_q,\hat S_q)$, monotone in both
arguments, with fixed charge $J_{Q,0}$:
\begin{equation}\label{eq:prepared-local}
J_{\mathrm{prep}}\leq J_0+\sum_{\kappa\in\mathcal{S}}J_\kappa(\hat n_\kappa)
+J_{Q,0}+\sum_{q\in\mathcal{Q}}J_q(\hat n_q,\hat S_q).
\end{equation}
No queue borrows the count, bytes, or local charge of another queue. Observation
pressure therefore cannot consume reserved action capacity.

\section{Session lifecycle}

\NcpStatus{proposed}

One bounded slot serializes open, replacement, and close for one namespace $\nu$. A
namespace is the triple of realm, session kind, and logical ID.
Figure~\ref{fig:lifecycle} shows the states.

\NcpFigure{lifecycle}{Session lifecycle owner. Terminal commit
publishes the result and high-water before it frees the slot.\label{fig:lifecycle}}

\subsection{Single flight}

Let $\mathcal{O}_\nu$ be the lifecycle records of namespace $\nu$. The number of busy
records is
\begin{equation}\label{eq:busy-count}
N_{\mathrm{busy}}(\nu)=\sum_{u\in\mathcal{O}_\nu}
\ind{\st(u)\in\{\textsc{pending},\textsc{ambiguous}\}}.
\end{equation}
The owner has one active slot for $\nu$. Each entry into a busy state first proves that
the slot is free. Therefore
\begin{equation}\label{eq:single-flight}
0\leq N_{\mathrm{busy}}(\nu)\leq1.
\end{equation}
A mutex cannot give this bound across processes. A shared writer must also hold one
fenced writer epoch.

\subsection{Transition order}

Let $c$ be the immutable backend coordinate of one operation. The reservation
transition makes the slot, the result cell, the prepared context, and the prior lineage
durable before any external work starts:
\begin{equation}\label{eq:reserve-order}
\mathrm{reserve}\ \prec\ \text{external work},
\end{equation}
where $a\prec b$ means that $a$ commits before $b$ starts. A capacity failure therefore
leaves no partial slot and no external effect. An unknown effect moves the same record
from \textsc{pending} to \textsc{ambiguous} with the same $c$. Reconciliation queries
that $c$ and then commits the record. Terminal commit has the order
\begin{equation}\label{eq:commit-order}
\mathrm{publish}(\text{result},\ \text{high-water})\ \prec\
\mathrm{free}(\text{slot}).
\end{equation}
A later operation cannot see a free slot without also seeing the retained result and
the advanced high-water.

\subsection{Exact retry}

A retained operation is the tuple $(c_r,m_r,z_r,o_r)$ of coordinate, exact request
bytes, exact admission-context bytes, and issuer ordinal. A retry $(c,m,z,o)$ is exact
only when
\begin{equation}\label{eq:exact-retry}
(c,m,z,o)=(c_r,m_r,z_r,o_r).
\end{equation}
The comparison of $m$ and $z$ is byte for byte. A digest can find the candidate record.
The receiver still compares the retained bytes before it returns or mutates anything.
Any unequal component is a conflict, which rejects without mutation.

\subsection{Checked ordinals}

For one issuer epoch, let $\hat o\in\mathbb{N}_{>0}$ with $\hat o\leq W$. The assignable
ordinals and the high-water sentinel are
\begin{equation}\label{eq:ordinal-domain}
o\in\{1,\ldots,\hat o\},\qquad o_{\mathrm{hw}}\in\{0,1,\ldots,\hat o\}.
\end{equation}
The value $o_{\mathrm{hw}}=0$ means that the epoch has committed no ordinal. A successor
exists only when $o_{\mathrm{hw}}<\hat o$. Then
\begin{equation}\label{eq:ordinal-successor}
o_{\mathrm{next}}=\cadd(o_{\mathrm{hw}},1)=o_{\mathrm{hw}}+1,\qquad
o_{\mathrm{hw}}<o_{\mathrm{next}}\leq\hat o.
\end{equation}
Checked addition cannot fail here because $o_{\mathrm{hw}}+1\leq\hat o\leq W$. When
$o_{\mathrm{hw}}=\hat o$, the epoch seals. An input with $o\leq o_{\mathrm{hw}}$ returns
the retained result, a retired result, or unavailability. It never executes again.

\subsection{No service per session}

Shared fixed-capacity tables serve all namespaces. The target is
\begin{equation}\label{eq:no-service}
N_{\mathrm{threads/session}}=N_{\mathrm{sockets/session}}
=N_{\mathrm{stores/session}}=0.
\end{equation}
Session data still exists. It lives in the bounded shared stores of
equation~\eqref{eq:lifecycle-memory}.

\section{Streams, positions, and fixed layouts}

\NcpStatus{proposed}

An accepted stream declaration compiles one immutable context. The context binds the
route, publisher incarnation, epoch, frame class, encoding, layout, position range,
replay profile, and overload policy.

\subsection{Positions}

For one stream epoch, let $\hat p\in\mathbb{N}_{>0}$ with $\hat p\leq W$:
\begin{equation}\label{eq:position-domain}
p\in\{1,\ldots,\hat p\},\qquad p_{\mathrm{hw}}\in\{0,1,\ldots,\hat p\}.
\end{equation}
A successor exists only when $p_{\mathrm{hw}}<\hat p$, and then
\begin{equation}\label{eq:position-successor}
p_{\mathrm{next}}=\cadd(p_{\mathrm{hw}},1)=p_{\mathrm{hw}}+1,\qquad
p_{\mathrm{hw}}<p_{\mathrm{next}}\leq\hat p.
\end{equation}
Otherwise the owner seals the epoch. It never wraps, saturates, or opens a new epoch
by itself. The allocator commits each position before encode, queue, or transport work.
A later failure leaves a visible gap. With $\mathcal{P}_{\mathrm{asg}}$ the assigned
and $\mathcal{P}_{\mathrm{pub}}$ the published positions,
\begin{equation}\label{eq:gap-set}
\mathcal{P}_{\mathrm{pub}}\subseteq\mathcal{P}_{\mathrm{asg}},\qquad
\mathcal{P}_{\mathrm{gap}}=\mathcal{P}_{\mathrm{asg}}\setminus\mathcal{P}_{\mathrm{pub}}.
\end{equation}
Assignment is strictly increasing, so no gap position can later name a different
payload.

\subsection{Fixed-layout frames}

A prepared frame has a header of $b_{\mathrm{hdr}}$ bytes, $n_v$ numeric values of
$w_{\mathrm{val}}$ bytes each, and $n_g$ availability groups. Each group has one
availability bit, so the bitmap takes
\begin{equation}\label{eq:bitmap-bytes}
a(n_g)=\left\lceil\frac{n_g}{8}\right\rceil
\end{equation}
bytes. A sensor layout has $n_g\geq1$, and its nonempty groups partition every sensor
value exactly once. A non-sensor layout has $n_g=0$. The frame length is
\begin{equation}\label{eq:frame-length}
\ell_{\mathrm{fix}}=b_{\mathrm{hdr}}+a(n_g)+n_vw_{\mathrm{val}}.
\end{equation}
For $0\leq n_v\leq\hat n_v$ and $0\leq n_g\leq\hat n_g$, the ceiling function is
nondecreasing, so
\begin{equation}\label{eq:frame-bound}
\ell_{\mathrm{fix}}\leq b_{\mathrm{hdr}}+\left\lceil\frac{\hat n_g}{8}\right\rceil
+\hat n_vw_{\mathrm{val}}.
\end{equation}
The receiver checks $n_v$ and the complete length with checked arithmetic before it
decodes any value. Names, units, ranges, and offsets live in the prepared layout, not
in each frame.

The bitmap uses bit $g$ for group $g$, least significant bit first. A set bit means
available. High padding bits are zero. An available group holds finite, in-range
values. An unavailable group forbids caller values, and the decoder returns typed
unavailability, never a placeholder value. The frame digest covers the header, the
bitmap, and every value byte. A received zero, an unavailable group, a malformed frame,
a transport gap, and a lost frame stay distinct.

For a direct linear decode, the work is the structural operation count
\begin{equation}\label{eq:codec-work}
\omega(n_v)=\omega_0+\omega_1n_v,
\end{equation}
with fixed counts $\omega_0$ for the header and $\omega_1$ for each value. It is not a
time measurement.

\section{Simulation steps}

\NcpStatus{proposed}

Opening, configuration, and close stay bounded JSON control operations. Repeated steps
use one prepared fixed-layout request and response pair. Figure~\ref{fig:sequence}
shows the exchange.

\NcpFigure{sequence}{Simulation session. Steps run strictly in
position order. Each result matches by generation, position, and request
digest.\label{fig:sequence}}

\subsection{Step window}

Let $\hat n_{\mathrm{step}}\in\mathbb{N}_{>0}$ be the window capacity and
$n_{\mathrm{open}}$ the number of reserved requests that are not terminal. Admission
requires
\begin{equation}\label{eq:window-admit}
n_{\mathrm{open}}<\hat n_{\mathrm{step}},
\end{equation}
which leaves one free slot, and after reservation
$n_{\mathrm{open}}+1\leq\hat n_{\mathrm{step}}$. Let $\hat b_{\mathrm{req}}$,
$\hat b_{\mathrm{res}}$, and $\hat b_{\mathrm{meta}}$ bound one request, one response,
and one metadata record, and $\hat b_{\mathrm{win}}$ the fixed window overhead. With
both directions reserved in advance,
\begin{equation}\label{eq:window-memory}
M_{\mathrm{win}}\leq\hat b_{\mathrm{win}}+\hat n_{\mathrm{step}}
\bigl(\hat b_{\mathrm{req}}+\hat b_{\mathrm{res}}+\hat b_{\mathrm{meta}}\bigr).
\end{equation}
Each active simulation session owns at most one window, and each window is charged to
one distinct session slot. The number of windows is therefore
$n_{\mathrm{win}}\leq\hat n_{\mathrm{ses}}$, and
\begin{equation}\label{eq:window-total}
M_{\mathrm{step}}=\sum_{w=1}^{n_{\mathrm{win}}}M_{\mathrm{win}}^{(w)}
\leq\hat n_{\mathrm{ses}}\Bigl[\hat b_{\mathrm{win}}+\hat n_{\mathrm{step}}
\bigl(\hat b_{\mathrm{req}}+\hat b_{\mathrm{res}}+\hat b_{\mathrm{meta}}\bigr)\Bigr].
\end{equation}
The local charge has the same form with one runtime unit:
$J_{\mathrm{step}}\leq\hat n_{\mathrm{ses}}\bigl[J_{\mathrm{win}}+\hat
n_{\mathrm{step}}J_{\mathrm{slot}}\bigr]$. A close can move a terminal response into the
retained-result store. That move and the window release form one atomic step.

\subsection{Execution order and correlation}

Let $p_{\mathrm{next}}$ be the next executable position of one generation. A request
at position $p$ starts only when
\begin{equation}\label{eq:step-order}
p=p_{\mathrm{next}},
\end{equation}
and definite completion sets $p_{\mathrm{next}}\leftarrow\cadd(p_{\mathrm{next}},1)$.
If that value is undefined, the owner seals the generation. An unresolved backend call
retires the generation. Arrival order never decides execution order.

The retained response is
\begin{equation}\label{eq:step-response}
\bigl(\mathrm{generation},\ p,\ \Hash(m_p),\ \mathrm{result}\bigr),
\end{equation}
where $m_p$ is the exact request at position $p$. A response satisfies only a waiter
with the same generation, position, digest, and exact request bytes. A reply never
takes the next waiter in arrival order. Every result carries
\texttt{is\_simulation\_output=true} and \texttt{calibrated\_posterior=false}.

\section{Plant command admission}

\NcpStatus{proposed}

The body issues live authority and command freshness. A serialized lease grants no
authority. Arrival never starts or extends a remote command lifetime.
Figure~\ref{fig:admission} shows the order.

\NcpFigure{admission}{Body command admission. ESTOP, HOLD, and
Active follow different paths to the effect boundary.\label{fig:admission}}

\subsection{Freshness grant}

Let $t_{\mathrm{iss}}$ be the receiver tick at which the body creates a freshness
grant, and $\hat\Delta\in\mathbb{N}_{>0}$ the profile lifetime in ticks of the same
clock incarnation. The exclusive deadline is
\begin{equation}\label{eq:deadline}
d=\cadd(t_{\mathrm{iss}},\hat\Delta).
\end{equation}
If $d$ is undefined, the body rejects the grant before it becomes visible. At tick $t$
of the same incarnation, the grant is live only when
\begin{equation}\label{eq:live}
t_{\mathrm{iss}}\leq t<d.
\end{equation}
An arrival tick is audit evidence only. Replacing $t_{\mathrm{iss}}$ with it would
create a new lifetime after network delay. A grant covers one contiguous position range
$[p_0,p_1]$ with $1\leq p_0\leq p_1\leq\hat p$, and admission also requires
\begin{equation}\label{eq:grant-range}
p_0\leq p\leq p_1.
\end{equation}
The position selects the grant. The frame repeats no grant, lease, or lifetime.

\subsection{Active predicate}

An Active command passes software admission only when all six predicates hold:
\begin{equation}\label{eq:active}
\phi_{\mathrm{active}}=\phi_{\mathrm{current}}\land\phi_{\mathrm{lease}}
\land\phi_{\mathrm{grant}}\land\phi_{\mathrm{stream}}\land\phi_{\mathrm{plant}}
\land\phi_{\mathrm{exec}}.
\end{equation}
The six predicates have these meanings:
\begin{itemize}[leftmargin=*]
  \item $\phi_{\mathrm{current}}$: the security snapshot and the session are current.
  \item $\phi_{\mathrm{lease}}$: the exact lease is live.
  \item $\phi_{\mathrm{grant}}$: equations~\eqref{eq:live} and~\eqref{eq:grant-range}
        hold.
  \item $\phi_{\mathrm{stream}}$: the epoch and the position pass the no-reuse checks.
  \item $\phi_{\mathrm{plant}}$: the plant profile accepts the channel, arity, units, and
        range.
  \item $\phi_{\mathrm{exec}}$: the bounded executor slot accepts the exact command.
\end{itemize}
The predicate stops at software admission.

\subsection{Restrictive modes}

HOLD needs an explicit known mode and a live holder. It follows ordinary stream order.
ESTOP can use the separately enrolled emergency lane when policy permits it. Neither
mode carries remote values. Their actions come from the installed plant profile. An
absent, \texttt{Init}, or unknown mode is a non-authorizing rejection. A rejected remote
request cannot report that a remote HOLD or ESTOP took effect.

\section{Effect boundary and closed-loop limits}

\NcpStatus{boundary proposed, stability arithmetic exact}

The body owner creates one bounded admission token that binds the exact command, plant
profile, generation, authority state, freshness state, and executor incarnation. The
actuator interface accepts no raw map, transport message, or serialized lease.

Let $e_a$ be the software admission event and $e_x$ a later physical effect. NCP
evidence can record $e_a$. It cannot establish $e_a\Rightarrow e_x$. Device,
mechanical, electrical, and plant-local safety systems stay outside the protocol. Each
deployment needs its own safety case and independent interlock.

\NcpFigure{closed-loop}{One feedback cycle. NCP records three
software events. It cannot measure the physical response.\label{fig:closed-loop}}

\subsection{Timing on one clock}

Let $t_s$, $t_a$, and $t_d$ be the sample, admission, and disposition ticks of one body
clock incarnation. When the events exist, the latencies are
\begin{equation}\label{eq:latencies}
\lambda_a=t_a-t_s,\qquad \lambda_d=t_d-t_s,
\end{equation}
and an admitted action with a later disposition satisfies $0\leq\lambda_a\leq
\lambda_d$. A rejected action can have no admission event, so $\lambda_a$ can be
undefined. An absent event never becomes zero. Differences between unrelated
publisher and receiver clocks are not equivalent measurements.

\subsection{Stability needs a plant model}

Consider a linear plant $\dot x(t)=A_cx(t)+B_cu(t)$ with state $x\in\mathbb{R}^{n_x}$
and input $u\in\mathbb{R}^{n_u}$. Assume exact state samples, no delay, no
saturation, and an input held constant over each sample period $\Delta>0$. Then
\begin{equation}\label{eq:zoh}
x_{k+1}=\Phi(\Delta)x_k,\qquad
\Phi(\Delta)=e^{A_c\Delta}+\left(\int_0^\Delta e^{A_c\theta}\,d\theta\right)B_cK
\end{equation}
for state feedback $u_k=Kx_k$ with gain matrix $K$. For a fixed period, the sampled
loop is asymptotically stable exactly when the spectral radius satisfies
$\rho(\Phi(\Delta))<1$.

For a scalar integrator $\dot x=u$ with $u_k=Kx_k$ and $K=-2\,\mathrm{s}^{-1}$, the
factor is
\begin{equation}\label{eq:scalar-loop}
\Phi(\Delta)=1-2\Delta.
\end{equation}
At $\Delta=0.1$~s, $\Phi=0.8$: each step keeps 80 percent of the error. At
$\Delta=1$~s, $\Phi=-1$: the error changes sign with no decay. Message delivery is the
same in both cases, so protocol success cannot show stability.

A variable period needs a stronger argument than one spectral radius for each period.
One sufficient condition is a common pair of symmetric positive-definite matrices
$P$ and $Q$ with $\Phi(\delta)^{\mathsf T}P\,\Phi(\delta)-P\preceq-Q$ for every admitted
period $\delta$. This report supplies no such pair for any ecosystem controller.

\section{Extensions and the complete state envelope}

\NcpStatus{proposed}

One extension message holds one complete bounded canonical-JSON envelope. Let
$\ell_{\mathrm{env}}$ be its length and $n_{\mathrm{att}}$ its number of attachment
references. Admission requires
\begin{equation}\label{eq:envelope}
0<\ell_{\mathrm{env}}\leq\hat\ell_{\mathrm{env}},\qquad
0\leq n_{\mathrm{att}}\leq\hat n_{\mathrm{att}},\qquad
\sum_{i=1}^{n_{\mathrm{att}}}\ell_{\mathrm{att},i}\leq\hat\ell_{\mathrm{att}},
\end{equation}
where $\ell_{\mathrm{att},i}$ is the declared length of attachment $i$. The installed
manifest selects one closed schema. It rejects unknown members, duplicate keys,
non-canonical numbers, and inline attachment bytes before any callback work.

Attachments come only from enrolled stores. The manifest fixes the exact HTTPS origin,
address set, TLS identity, credential source, timeouts, media types, and byte limits.
The wire cannot supply a URL, local path, or redirect target. The receiver reserves all
resources first. It checks each declared length and digest before semantic use. A cut
during a fetch prevents the callback. NCP~1.0 defines no generic chunk-reassembly
protocol.

Let $\hat n_{\mathrm{ext}}$ bound the envelope slots of one activation. Let
$\hat b_{\mathrm{ext}}$ bound the larger of the active and terminal metadata of one
slot, and let $\hat b_{\mathrm{act}}$ be the fixed charge of one activation. Each activation consumes one
prepared-context unit, so the activation count is at most $\hat n_{\mathrm{ctx}}$:
\begin{equation}\label{eq:extension-memory}
M_{\mathrm{ext}}\leq\hat n_{\mathrm{ctx}}\Bigl[\hat b_{\mathrm{act}}
+\hat n_{\mathrm{ext}}\bigl(\hat\ell_{\mathrm{env}}+\hat b_{\mathrm{ext}}\bigr)\Bigr].
\end{equation}
A context stays charged while any slot or terminal record refers to it, so a retained
record cannot escape the factor $\hat n_{\mathrm{ctx}}$. The local charge
$J_{\mathrm{ext}}$ has the same form.

\subsection{Complete bounded state}

Let $\mathcal{Y}=\{\mathrm{rx},\mathrm{json},\mathrm{att},\mathrm{parse},
\mathrm{callback}\}$ name receive scratch, JSON arenas, attachment storage, extension
parser arenas, and callback buffers. Each domain $y$ has a portable ceiling
$\hat b_y$, with fixed charge $\hat b_{Y,0}$:
\begin{equation}\label{eq:aux}
M_{\mathrm{aux}}\leq\hat b_{Y,0}+\sum_{y\in\mathcal{Y}}\hat b_y.
\end{equation}
All domains are disjoint, so the complete NCP-owned state satisfies
\begin{equation}\label{eq:total}
M_{\mathrm{NCP}}\leq M_{\mathrm{prep}}+M_{\mathrm{step}}+M_{\mathrm{ext}}
+M_{\mathrm{aux}},
\end{equation}
with the same form for the local charge. The sum applies no alias discount. A borrowed
view is charged to its owner, and a copy is a second charge. During a transfer between
owners, both stay reserved until the destination commits. The bound excludes code,
thread stacks, device memory, and unrelated process state.

\subsection{Dependency direction}

Let $\mathcal{G}=(\mathcal{V},\mathcal{E})$ be the repository dependency graph. An edge
$(v,w)\in\mathcal{E}$ means that $v$ depends on $w$. Let $v_{\mathrm{NCP}}$ be NCP and
$\mathcal{C}$ the consumer repositories that integrate NCP. Write
$v\rightsquigarrow w$ for a directed path from $v$ to $w$. The required direction is
\begin{equation}\label{eq:dependency}
\forall c\in\mathcal{C}:\ (c,v_{\mathrm{NCP}})\in\mathcal{E}\ \land\
\neg\bigl(v_{\mathrm{NCP}}\rightsquigarrow c\bigr).
\end{equation}
The first condition makes each consumer use the NCP package instead of a copy of the
protocol files. The path condition also forbids an indirect dependency of NCP on a
consumer. A consumer-specific fork therefore cannot become an NCP requirement.

\subsection{Fleet profile}

The selected fleet profile uses one composite session for each run with $N\in\{1,2,3\}$
