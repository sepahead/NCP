# First development-profile decision

Status: bounded development-reference decision. Complete final product v1 requirements remain open.

The supplied review recommends a native NCP boundary with exact causality and recoverable outcomes.
Its source findings are hypotheses until the implementation and operating evidence establish them.
Its finite mathematical examples do not validate a native service or simulator.

This decision selects one reproducible local reference experiment for development.
It preserves the failed requirements of the broader candidate.
It adds a new explicit contract and acceptance matrix instead of marking old rows complete.
It does not select the complete final product architecture or require all applications in every composition.

## Product requirements remain open

The final product must support independently selectable adapters and optional project combinations.
CREBAIN must work standalone and support declared experiments with many drones and multiple actual sensor modalities.
Prisoma must own embodied-agent and world-model experiments, with CREBAIN available as a simulation dependency.
Engram integration must remain optional.
Camera/3DGS, audio, and heat profiles require explicit data contracts and evidence for each claimed sensor behavior.

The current four-owner, one-through-three-entity profile remains a fixed reference control.
Its implementation does not establish those broader product requirements.
The [owning guide](README.md#open-final-v1-requirements) keeps those requirements open without changing the reference wire, limits, or registry identity.

## Ten credible approaches

These alternatives describe the initial reference-profile choice.
They do not resolve the open final product requirements.

| Approach | Assumption and expected benefit | Failure mode | Decisive experiment |
| --- | --- | --- | --- |
| Complete every broad-candidate feature first | All remote, physical, and policy features are required for local science. One release covers every role. | Unrelated deployment prerequisites prevent a useful bounded local experiment. | Demonstrate that local causal correctness requires a remote or physical capability. |
| Explicit local successor | A deterministic local profile can stand alone. It permits a smaller complete acceptance gate. | Marketing quietly inherits excluded broad-candidate claims. | Attempt every excluded profile and inspect all public status surfaces. |
| Accelerate serialization first | Transport encoding dominates the useful error budget. | A faster incorrect schedule still changes the controller experiment. | Compare matched trajectories before and after fixing causal step order. |
| Reuse project kernels behind native NCP owners | Existing kernels have stronger evidence than replacements. | A wrapper retains a hidden Host API or direct-engine bypass. | Trace actual process communication and reject forbidden paths. |
| Rewrite all kernels | One implementation can remove legacy assumptions. | Reimplementation creates new scientific and behavioral errors. | Differentially reproduce each existing qualified kernel result. |
| Use a central runtime broker | Central scheduling reduces peer complexity. | The broker acquires application ownership and becomes another failure boundary. | Remove the broker while retaining contract and owner behavior. |
| Use one owner per mutable project process | Serial state ownership makes causal execution inspectable. | A stuck owner blocks progress without a tested containment path. | Kill or stall each owner at every coupled-step boundary. |
| Enable Haldir and online guard immediately | Policy-constrained experiments are required now. | Missing acceleration semantics or advisory authority creates an unsafe fallback. | Select gated mode and test all direct-command bypasses. |
| Record-only monitoring with explicit abstention | Diagnostic evidence is useful without command authority. | A favorable label is mistaken for permission or scientific validation. | Forge a nominal report and attempt every command or reset operation. |
| Publish only after installed reproduction | A clean installation exposes packaging and hidden dependency faults. | Local worktree success is presented as reproducible distribution. | Build and run exact consumers outside the provider workspace. |

The reference combination uses the explicit local successor, native project owners, record-only monitoring, and installed reproduction.
It reuses actual kernels and preserves independent data validation.
It defers remote and gated profiles with explicit rejection controls.
Serialization improvements are accepted only when exact scientific values and outcome identity remain intact.

## Five review lenses

| Lens | Strongest requirement | Evidence that can falsify the design |
| --- | --- | --- |
| Scientific validity | Actual simulator and detector execution retain their assumptions and missingness. | A reused seed hides changed dynamics, an absent sample becomes zero, or one modality becomes a nominal cross-modal report. |
| Runtime correctness | A command has one exact predecessor, one owner, and one known or indeterminate outcome. | A lost reply advances twice or an unclosed pair permits the next dependent step. |
| Security and provenance | Installed channel custody and bounded data precede role-specific mutation. | A payload chooses its role, a child inherits peer state handles, or a hidden direct route remains reachable. |
| Statistics and generalization | Synthetic controls, actual producer observations, and measured timing have separate evidence classes. | A synthetic positive control is relabeled as real CREBAIN evidence or unrelated latency percentiles are subtracted. |
| Maintenance and operations | One shared descriptor has independent consumers and clean installed reproduction. | A workspace patch, mutable source, or private file is necessary to reproduce the advertised run. |

A failed lens blocks its claim even when the other lenses pass.
Visual quality helps review the boundary.
It supplies no implementation or scientific evidence.

## Assumptions that were challenged

The named Galadriel magnitude detector requires at least two modalities.
Actual CREBAIN evidence in the selected adapter supplies one Visual modality with three innovation dimensions.
Three dimensions are not three independent modalities.
The correct native result is therefore insufficiency, with a separate synthetic two-modality control for detector sensitivity.

NIS has a chi-square reference only under explicit observation and covariance assumptions.
A numerical NIS value and positive declared dimension do not establish calibration.
The adapter preserves the actual residual and covariance source record without fabricating those assumptions.

Persistent NEST state does not imply arbitrary runtime stimulus updates are legal.
Only the selected, tested update mechanism can be admitted.
The readout interval must account for the exact recording delay and endpoint convention.

Exact integer time does not establish real-time freshness.
Logical pause duration and wall-clock age remain different quantities.
The local profile makes no physical freshness or end-to-end deadline claim.

Private pipes do not create an operating-system sandbox.
The selected Darwin design adds explicit file, network, process, and signal denial with a separate child-lifetime guardian.
Fixed endpoint roles and those operating-system controls require separate negative tests.
The original bypass tests cannot be declared passed from package structure alone.
Development tests now exercise direct Darwin denials and owned-process cleanup.
These observations apply to trusted installed applications, with complete release qualification still open.
The additional worker timer does not guarantee termination of arbitrary malicious code.
The selected boundary does not claim complete Mach or process-metadata isolation.

The coordinator also compared ten containment approaches.
These included trust in same-user processes, API roles alone, pipes alone, sandboxing alone, containers, and the previous Host API launcher.
The remaining approaches used pipes with sandbox and guardian, a central proxy, remote SSH, or Linux-specific syscall restrictions.
The selected combination uses pipes with a Darwin sandbox and a lifecycle-only guardian.
It limits the qualification target to the actual host and keeps application data in NCP.
Sandboxing alone does not close orphan lifetime after parent death.
The other host and remote approaches introduce unqualified runtime or transport assumptions.

An exact digest requires an exact numeric representation.
Actual Galadriel output exposed a one-bit parser change in a probability value.
The shared JSON parser now selects exact binary64 round trips.
The retained regression checks the original value rather than a rounded replacement.
